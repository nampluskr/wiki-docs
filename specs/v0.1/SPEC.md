# SPEC — wiki-docs v0.1

## R-1. 위키 페이지는 wiki/ 아래 분야별 폴더에 있고, 빈 분야 폴더가 없다

**요구**

위키 페이지는 `wiki/<분야>/`에 둔다. 분야 폴더는 그 분야의 첫 페이지를 저장할 때 사람에게 분야를 확인받아 만든다.

**정해진 결과**

`wiki/` 바로 아래에는 `index.md`와 분야 폴더만 있다. 분야 폴더마다 `index.md` 말고 페이지가 하나 이상 있다.

**판정 방법**

`wiki/` 바로 아래 목록과 분야 폴더마다의 파일 수를 본다.

**출처**

## R-2. wiki/ 이름은 영문 소문자·숫자·하이픈만 쓰고, raw/는 폴더 이름만 영어다

**요구**

`wiki/` 아래 폴더·파일 이름은 `[a-z0-9-]`와 확장자만 쓴다. 한글 제목은 frontmatter `title`과 본문에 쓴다. `raw/` 아래 폴더 이름은 영어로 짓고, 파일 이름은 원래 이름(한국어·영어)을 그대로 둔다.

**정해진 결과**

`wiki/` 아래에 `[a-z0-9-.]` 밖의 글자가 들어간 이름이 없다. `raw/` 아래 폴더 이름에 한글이 없다. `raw/` 파일 이름이 `inbox/`에 들어왔을 때와 같다.

**판정 방법**

`wiki/`·`raw/` 아래 이름을 목록으로 뽑아 허용 밖 글자를 찾는다. `git log --follow`로 raw 파일의 이름이 inbox에서 옮겨질 때 바뀌지 않았는지 본다.

**출처**

## R-3. inbox 원본은 정리 후 raw/<분야>/에 있고, 옮긴 뒤 바뀌지 않는다

**요구**

`inbox/`에는 사람이 원본을 넣거나(GitHub 웹 업로드 포함), 사람의 요청으로 에이전트가 넣는다. 원본은 마크다운 문서를 담은 폴더와 유튜브 자막·요약이다. 에이전트는 요청을 받으면 위키 페이지로 정리하고 원본을 폴더 구조 그대로 `raw/<분야>/`로 옮긴다. 분야를 정할 수 없는 원본은 옮기지 않고 묻는다. 외부 검색 자료는 `raw/`에 두지 않는다.

**정해진 결과**

정리가 끝난 원본은 `inbox/`에 없고 `raw/<분야>/`에 있다. `raw/` 분야 폴더 이름은 `wiki/` 분야 폴더 이름 중 하나다. `raw/` 파일은 옮겨진 뒤 내용이 바뀐 이력이 없다.

**판정 방법**

정리 작업 뒤 `inbox/`를 본다. `git log --follow`로 `raw/` 파일의 이동 뒤 수정 이력을 본다.

**출처**

## R-14. 유튜브 원본은 사람이 고른 것(자막·요약·둘 다)만 텍스트로 inbox에 들어온다

**요구**

유튜브 링크를 받으면 무엇을 받을지 사람에게 묻는다. 자막은 cpu 환경의 youtube-kit으로 트랙 목록을 보여 주고 사람이 고른 트랙만 받는다. 요약은 ego-lite에서 YouTube 요약 기능으로 가져온다. 영상·음성 파일은 받지 않는다. 가져오지 못하면 다른 것으로 대신하지 않고 사람에게 알린다.

**정해진 결과**

유튜브 원본은 영상마다 `youtube-<영상ID>/` 폴더 하나이고, 그 안에 `<영상ID>.meta.json`이 항상 있다. 자막(`<영상ID>.<종류>.<키>.srt`)과 `summary.md`(맨 위에 영상 URL·가져온 날짜)는 사람이 고른 것만 있다. `inbox/`·`raw/`에 영상·음성 파일이 없다.

**판정 방법**

유튜브 원본 폴더의 파일 목록과 대화 기록의 선택을 대조하고, 영상·음성 확장자 파일을 찾는다.

**출처**

## R-4. 위키 페이지는 frontmatter 다섯 항목을 갖고, 출처를 밝힌다

**요구**

`index.md`를 뺀 모든 위키 페이지는 `title`, `sources`, `updated`, `tags`, `status`를 둔다. `sources`는 문자열 목록이고, 원본의 `raw/` 경로를 그대로 적거나 외부 검색 자료의 URL 뒤에 ` (YYYY-MM-DD)` 확인 날짜를 붙여 적는다. 새 페이지는 `draft`이고, `stable`은 사용자 지시로만 바뀐다.

**정해진 결과**

모든 페이지에 다섯 항목이 있다. `status`는 `draft`·`stable` 중 하나다. `sources`의 `raw/` 경로는 실제 파일을 가리키고, URL 항목에는 확인 날짜가 있다. 내용이 있는 페이지의 `sources`가 비어 있지 않다.

**판정 방법**

페이지마다 frontmatter를 읽어 항목·값·경로를 확인한다.

## R-6. wiki/index.md와 분야 index.md가 실제 페이지 목록과 맞는다

**요구**

`wiki/index.md`는 모든 분야를, 분야 `index.md`는 그 분야의 모든 페이지를 링크한다. 페이지·분야가 바뀌면 같이 고친다.

**정해진 결과**

분야 폴더마다 `index.md`가 있다. 분야 `index.md`의 링크 목록과 폴더의 페이지 목록이 같다. `wiki/index.md`의 분야 목록과 분야 폴더 목록이 같다.

**판정 방법**

폴더 목록과 `index.md` 링크 목록을 비교한다.

## R-8. 질문을 받으면 위키를 먼저 찾고, 그다음에 외부 검색을 한다

**요구**

에이전트는 질문을 받으면 `wiki/index.md`·분야 `index.md`를 보고, 못 찾으면 `wiki/` 본문을 키워드로 검색한다. 위키에 없거나 사용자가 더 자세히 요청할 때만 외부 검색을 한다. 외부 검색은 에이전트 기본 웹 검색으로 하고, 로그인이 필요한 페이지는 ego-lite로 가져온다.

**정해진 결과**

답에 위키를 찾아본 결과(찾은 페이지 경로, 또는 "위키에 없음")가 외부 검색 결과보다 먼저 나온다.

**판정 방법**

흐름 확인용 질문(R-12)의 답을 읽어 순서를 본다.

## R-9. 답은 출처를 나눠 보여 주고, 위키 저장은 사용자 확인 뒤에만 한다

**요구**

위키 내용에는 페이지 경로를, 외부 검색 내용에는 URL을 붙여 구분한다. 외부 검색을 했으면 답 끝에 "위키에 추가할까요?"를 묻는다. 사용자가 예라고 하거나 먼저 지시했을 때만 저장한다.

**정해진 결과**

외부 검색을 한 답마다 출처 구분과 추가 여부 질문이 있다. 위키에 저장된 내용마다 그에 앞선 사용자의 확인이나 지시가 있다.

**판정 방법**

답과 대화 기록, 저장 커밋을 대조한다.

**출처**

## R-10. 기존 페이지와 겹치면 보태고, 다르면 고치기 전에 묻는다

**요구**

새 내용 중 기존 페이지에 없던 것은 그 페이지에 보태고 `sources`·`updated`를 고친다. 기존 내용과 다르면 두 내용을 보여 주고 묻는다.

**정해진 결과**

같은 주제의 페이지가 둘 이상 생기지 않는다. 기존 내용을 바꾼 커밋마다 그에 앞선 사용자의 답이 있다.

**판정 방법**

분야 `index.md`에서 주제가 겹치는 페이지를 찾고, 내용을 바꾼 커밋을 대화 기록과 대조한다.

**출처**

## R-13. 작업 시작 때 pull하고 끝날 때 commit하며, push는 확인받는다

**요구**

에이전트는 작업 전에 `git pull`, 작업 후 커밋한다. `push`는 매번 사람에게 확인받은 뒤 한다.

**정해진 결과**

사람의 확인 없이 push된 커밋이 없다. 작업 커밋이 원격의 최신 커밋 위에 쌓인다.

**판정 방법**

작업 기록에서 pull과 push 전 확인을 본다. `git log --graph`로 불필요한 병합 커밋이 없는지 본다.

**출처**
