# PLAN — wiki-docs v0.1

## 읽는 법과 이 순서에 걸린 규칙

`R-n`은 v0.1 `SPEC.md`의 요구, `D-n`은 v0.1 `DECISIONS.md`의 결정, `UC-n`은 루트 `USECASES.md`의 시나리오다.

순서의 이유: 지침(WIKI.md)과 뼈대가 있어야 에이전트가 흐름을 따를 수 있으므로 Phase 1이 먼저다. 버전의 목적인 질문 흐름(Phase 2)을 원본 정리(Phase 3)보다 먼저 돌려, Phase 3에서 기존 페이지에 보태는 경우(R-10)를 만날 수 있게 한다. 전체 판정과 push는 마지막(Phase 4)이다.

순서 변경(2026-11-01): 사용자 지시("Phase 3 먼저 진행")로 Phase 3을 Phase 2보다 먼저 한다. 그래서 Phase 3에서는 R-10(기존 페이지에 보태기)을 Phase 2 페이지와 겹쳐 확인할 수 없고, Phase 3의 두 원본끼리 겹칠 때나 Phase 2에서 확인한다.

모든 Phase에 걸리는 규칙:

- 작업 전에 `git pull`, 작업 후 커밋한다. push는 사람에게 확인받는다(D-14).
- 질문·원본·분야처럼 사람이 정할 것은 Phase를 시작할 때 묻고, 지어내지 않는다(AGENTS).
- Phase를 끝낼 때마다 `PROGRESS.md`에 무엇을·결과·검증을 남긴다(AGENTS).

## Phase 1 — 뼈대와 지침

**목적** — 에이전트가 따를 작업 지침과 위키의 빈 뼈대를 만든다.

**대응** — R-11 · R-6 · D-3 · D-7 · D-12 · D-19

**완료 조건**
- 루트 `WIKI.md`가 있고, R-1~R-10·R-13·R-14의 규칙과 UC-1~UC-9의 절차가 들어 있다.
- `AGENTS.md`에 "위키 작업은 WIKI.md를 따른다"는 줄이 있다.
- `wiki/index.md`가 있다(분야 목록은 비어 있음).
- `inbox/.gitkeep`, `raw/.gitkeep`이 있다.
- `.gitignore`에 `.serena/`가 있다.
- 커밋되어 있다.

## Phase 2 — 질문 흐름 한 번 (UC-2 → UC-4)

**목적** — 실제 질문 하나로 위키 검색 → 외부 검색 → 사용자 확인 → 위키 저장을 처음부터 끝까지 거친다.

**대응** — R-1 · R-2 · R-4 · R-5 · R-6 · R-7 · R-8 · R-9 · R-12 · D-1 · D-5 · D-9 · D-10 · D-17 · D-18

**완료 조건**
- 사람이 Phase 시작 때 질문을 정했다.
- 답에 위키 검색 결과("위키에 없음" 포함)가 외부 검색 결과보다 먼저 나오고, 출처(페이지 경로·URL)가 나뉘어 있으며, 끝에 "위키에 추가할까요?"가 있다.
- 사람의 확인 뒤에 첫 분야 폴더(분야 이름은 사람이 확인)와 페이지가 생겼다.
- 페이지가 R-2·R-4·R-5·R-7을 만족하고, 분야 `index.md`와 `wiki/index.md`에 들어 있다.
- 과정이 `PROGRESS.md`에 기록되고 커밋되어 있다.

## Phase 3 — inbox 원본 정리 한 번씩 (UC-6 · UC-7)

**목적** — 마크다운 폴더 하나와 유튜브 영상 하나를 inbox에서 위키로 정리해 raw/로 옮긴다.

**대응** — R-2 · R-3 · R-10 · R-14 · D-2 · D-3 · D-11 · D-13 · D-15 · D-16

**완료 조건**
- 사람이 Phase 시작 때 마크다운 폴더를 `inbox/`에 넣고 유튜브 링크를 주었다.
- 유튜브는 사람이 고른 것(자막·요약·둘 다)만 `inbox/youtube-<영상ID>/`에 들어왔고, `meta.json`이 있으며, 영상·음성 파일이 없다.
- 두 원본이 위키 페이지로 정리되었고, 페이지 `sources`가 `raw/` 경로를 가리킨다.
- 두 원본이 `inbox/`에 없고 이름·구조 그대로 `raw/<분야>/`에 있다.
- 기존 페이지와 겹친 내용이 있었으면 R-10대로 보태거나 사람에게 물었다. 겹친 내용이 없었으면 그렇다고 `PROGRESS.md`에 적었다.
- 과정이 `PROGRESS.md`에 기록되고 커밋되어 있다.

## Phase 4 — 전체 점검과 동기화 (UC-9)

**목적** — 요구 R-1~R-14를 판정하고, 사람의 확인을 받아 push한다.

**대응** — R-1~R-14 · D-14

**완료 조건**
- `PROGRESS.md`에 R-1~R-14 각각의 판정(충족 / 미충족과 이유)이 있다.
- 미충족이 있으면 고쳤거나, 사람이 다음 버전으로 넘기기로 했다.
- 사람에게 확인받고 push했다.
- `PROGRESS.md` 버전 종료 절에 사람의 종료 판단과 남은 것이 적혀 있다.
