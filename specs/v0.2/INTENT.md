# INTENT — wiki-docs v0.2

## 목적·범위·기대 결과

- 목적: 위키를 분야와 자료 소스로 나누는 구조로 다시 정하고, inbox에 남은 원본을 그 구조로 위키에 반영한다.
- 범위:
  - 위키 구조 재정의. `wiki/<분야>/<소스>/`로 나누고, 소스는 `youtube`·`web` 두 개다(같은 날 사용자 지시로 `docs`를 `web`에 합침).
  - inbox·raw 폴더 이름 규칙 재정의. `YYMMDD-{소스}-{title-in-kebab-case}`.
  - raw를 소스로 나누기. 최종 규칙은 `raw/{소스}/YYMMDD-{title}/`이고 분야로 나누지 않는다(같은 날 사용자 지시로 추가·개정).
  - 유튜브 페이지 양식. 주제 단위 페이지 안을 영상별 섹션으로 나누고 등록일 최신순으로 둔다(같은 날 사용자 지시로 추가).
  - 분야 정리. `apps` 분야를 두지 않는다(앱은 독립 레포에서 관리).
  - v0.1에서 만든 페이지 3개와 원본 2개를 새 구조·새 이름으로 옮기기.
  - inbox에 남은 원본 3개(rust-gui, ego-lite-guide, ssh-tailscale-remote-terminal-guide)를 새 구조로 `dev`에 반영하기.
- 기대 결과: 위키 페이지가 모두 `wiki/<분야>/<소스>/`에 있고, 원본이 모두 새 이름 규칙으로 `raw/`에 있으며, `inbox/`에 정리되지 않은 원본이 남아 있지 않다.

## 배경

v0.1에서 위키 뼈대와 질문·원본 정리 흐름을 한 번씩 확인하고 종료했다.
노트북에서 올린 원본 7개 중 1개(herdr)만 정리했고 6개가 inbox에 남았다.
사용자가 위키를 분야 아래 자료 소스로 나누고 싶다고 했고(예: `dev/youtube`), inbox·raw 폴더 이름도 날짜·소스·제목이 드러나게 다시 정하기로 했다.
그 뒤 사용자가 앱 관련 원본 3개(rust-video-player, rust-video-player-native, zed-like-editor)를 inbox에서 지웠다. 앱은 독립된 레포로 관리하기 때문이다. 그래서 `apps` 분야를 없애고, 남은 원본 3개를 `dev`로 정리한다.

## 제외 범위

- 큰 원본을 페이지로 나누는 기준.
  남은 원본에 큰 원본이 없다. 필요해질 때 정한다.
- 마크다운이 아닌 파일(이미지 등).
  남은 원본에 이미지가 없다. 필요해질 때 정한다.
- 여러 에이전트 분담.
  원본 정리를 scouter에게 나눠 맡기지 않는다.
- 미확인 규칙을 일부러 확인하기.
  R-7(수식)·UC-5(내용이 다를 때 묻기)는 정리하다가 생기면 확인하고, 그러려고 따로 질문이나 원본을 만들지 않는다.
- herdr `send-keys` 문제의 원인 조사.
- 자동 실행.
  정해진 시간에 에이전트가 스스로 검색·정리·갱신하지 않는다(v0.1과 같음).
- 웹 사이트로 게시.
  위키를 별도 웹사이트나 검색 화면으로 만들지 않는다(v0.1과 같음).
