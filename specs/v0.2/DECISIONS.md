# DECISIONS — wiki-docs v0.2

**선택**

| v0.1 결정 | 바뀌는 부분 | 바꾸는 v0.2 결정 |
| --- | --- | --- |
| D-1 분야별 폴더 | 분야 아래에 소스 폴더를 둔다 | D-2 |
| D-2 이름 규칙 | inbox·raw 폴더 이름 규칙 | D-4 |
| D-3 원본 보관 | raw 폴더 이름·위치를 규칙에 맞출 때만 바꿀 수 있다 | D-5 |

**배제한 대안**

- **v0.1 결정을 모두 옮겨 적기** — 같은 내용이 두 곳에 생긴다. 배제.

## D-2. 위키 페이지는 wiki/<분야>/<소스>/에 두고, 소스는 youtube·docs·web이다

**선택**

```text
wiki/<분야>/
  index.md
  youtube/<페이지>.md     유튜브 영상에서 만든 페이지
  docs/<페이지>.md        사람이 넣은 마크다운 문서에서 만든 페이지
  web/<페이지>.md         외부 웹 검색으로 만든 페이지, 또는 소스가 둘 이상 섞인 페이지
```

소스 폴더도 분야 폴더처럼 미리 만들지 않고, 그 소스의 첫 페이지를 저장할 때 만든다. 페이지 파일 이름은 v0.1 D-2대로 영문 소문자·숫자·하이픈이고 날짜를 붙이지 않는다.

**근거**

사용자 지시 "위키는 wiki\{분야}로 나누고 하위 폴더는 자료의 소스로 나누고 싶습니다. 즉, dev\youtube가 추가되어야 합니다." 사용자 답 "youtube · docs · web".

**배제한 대안**

- **youtube·docs 두 개** — 사용자가 고르지 않았다. 배제.
- **원본 폴더별 하위 폴더** — 사용자가 고르지 않았다. 배제.

---

## D-3. 소스가 하나면 그 소스 폴더에, 둘 이상이면 web에 두고, 나중에 섞이면 web으로 옮긴다

**선택**

- 페이지의 `sources`가 한 소스에서만 왔으면 그 소스 폴더에 둔다.
- 둘 이상의 소스가 섞였으면 `web/`에 둔다. 직접 겪은 일(v0.1 D-17의 저장소 안 기록 문서)은 소스 종류를 늘리지 않는다.
- 이미 있는 페이지에 다른 소스의 내용을 보태 섞이게 되면, 같은 커밋에서 페이지를 `web/`으로 옮기고 그 페이지를 가리키는 링크와 분야 index를 함께 고친다.

**근거**

사용자 답 "web으로 해 주세요"(섞인 페이지), "옮김 (규칙 그대로)"(나중에 섞일 때).

**배제한 대안**

- **혼합용 폴더 따로** — 사용자가 web을 골랐다. 배제.
- **처음 위치 유지** — 링크가 깨지지 않지만 사용자가 규칙대로 옮기기를 골랐다. 배제.

---

## D-4. inbox·raw의 원본 폴더 이름은 YYMMDD-{소스}-{title}이다

**선택**

- 형식: `YYMMDD-{소스}-{title-in-kebab-case}`. 예) `261101-docs-rust-gui`, `261101-youtube-claude-skill-writing-rules`
- `YYMMDD`: 원본을 inbox에 넣은 날. raw로 옮겨도 바꾸지 않는다.
- `{소스}`: `youtube` 또는 `docs`. 외부 웹 검색 자료는 원본을 두지 않으므로(v0.1 D-4) `web`인 원본 폴더는 없다.
- `{title}`: 넣는 사람이 짓는다. 규칙과 다른 이름으로 들어오면 에이전트가 원래 폴더 이름이나 제목으로 새 이름을 제안하고 확인받아 바꾼다.
- 유튜브의 `{title}`은 영상 제목을 영문으로 요약한 것이다. 영상 ID는 폴더 안 파일 이름(`<영상ID>.meta.json` 등)에 남는다.
- 원본 하나가 파일 하나여도 폴더로 둔다.
- 폴더 안의 파일 이름은 바꾸지 않는다(v0.1 D-2·D-16).

**근거**

사용자 지시 "inbox, raw의 폴더명 규칙 재정의: YYMMDD-{소스}-{title-in-kebab-case}". 사용자 답 "inbox에 넣은 날", "넣는 사람이, 없으면 에이전트", "영상 제목 영문 요약".

**배제한 대안**

- **원본이 만들어진 날, 정리한 날** — 사용자가 고르지 않았다. 배제.
- **항상 에이전트가 제안** — 사용자가 고르지 않았다. 배제.
- **유튜브 title을 영상 ID로** — 사용자가 고르지 않았다. 배제.

---

## D-5. raw는 raw/<분야>/<원본 폴더>/이고, 이 규칙에 맞출 때만 폴더 이름·위치를 바꿀 수 있다

**선택**

원본은 정리 후 `raw/<분야>/<YYMMDD-소스-title>/`에 둔다. 소스 하위 폴더는 두지 않는다(폴더 이름에 소스가 있다). 원본 파일의 내용과 이름은 그대로 두고, 폴더 이름과 위치만 이 규칙에 맞추려고 바꿀 수 있다.

**근거**

사용자 답 "raw/<분야>/<이름>/". v0.1 D-3 "옮긴 뒤로는 고치지 않는다"는 파일 내용을 지키려는 것이고, 폴더 이름 변경(`git mv`)은 내용을 바꾸지 않는다.

**배제한 대안**

- **raw/<이름>/ 평평하게** — 사용자가 고르지 않았다. 배제.

---

## D-6. 목차는 분야 index 하나에 소스별 제목을 둔다

**선택**

`wiki/<분야>/index.md` 하나에 `## youtube`, `## docs`, `## web` 제목을 두고 그 아래에 페이지를 한 줄씩 링크한다. 페이지가 없는 소스의 제목은 두지 않는다. 소스 폴더에는 index를 두지 않는다. `wiki/index.md`는 v0.1 D-7대로 분야 목록이다.

**근거**

사용자 답 "분야 index 하나, 소스별 제목".

**배제한 대안**

- **소스마다 index** — 목차가 3단이 된다. 사용자가 고르지 않았다. 배제.

---

## D-7. apps 분야를 두지 않는다

**선택**

v0.1 D-20의 `apps`를 두지 않는다. 분야는 지금 `dev` 하나이고, 새 분야는 v0.1 D-1대로 필요할 때 확인받아 만든다. `rust-gui`(Rust GUI 프레임워크 설치·비교)는 특정 앱이 아닌 개발 도구 지식으로 보고 `dev`에 둔다.

**근거**

사용자 지시 "inbox에서 app 관련 폴더를 제거했습니다. 앱은 독립된 레포로 관리되기 때문". 사용자 답 "없애기", "남겨서 dev로 정리". 루트 INTENT 다루지 않는 것 "각 프로젝트 레포의 docs/에 속하는 문서".

**배제한 대안**

- **apps 남겨 두기** — 사용자가 고르지 않았다. 배제.
