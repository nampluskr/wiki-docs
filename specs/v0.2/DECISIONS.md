# DECISIONS — wiki-docs v0.2

## D-1. v0.1의 결정은 이 문서에서 바꾸지 않은 것을 그대로 따른다

**선택**

v0.1 D-1~D-20 가운데 아래 결정이 바꾸는 부분만 고치고, 나머지는 그대로 따른다. 바뀌는 v0.1 결정은 다음과 같다.

| v0.1 결정 | 바뀌는 부분 | 바꾸는 v0.2 결정 |
| --- | --- | --- |
| D-1 분야별 폴더 | 분야 아래에 소스 폴더를 둔다(소스는 web·youtube) | D-2 · D-10 |
| D-2 이름 규칙 | inbox·raw 폴더 이름 규칙 | D-4 · D-10 |
| D-3 원본 보관 | raw 폴더 이름·위치를 규칙에 맞출 때만 바꿀 수 있다, raw는 raw/{소스}/YYMMDD-{title} | D-5 · D-9 · D-12 |
| D-11 기존 페이지에 보태기 | 유튜브는 영상 섹션(등록일·최신순)을 더한다 | D-11 |
| D-4 외부 검색 원본 | 웹 정보를 정리한 문서 원본은 raw/<분야>/web/에 둔다(질문 중 웹 검색은 그대로 URL만) | D-10 |
| D-7 목차 | 분야 index 안을 소스별로 나눈다 | D-6 |
| D-16 유튜브 원본 모양 | 폴더 이름 | D-4 |
| D-20 첫 분야 | `apps`를 두지 않는다 | D-7 |

**근거**

v0.1 PROGRESS의 남은 것과 v0.2 INTENT 범위. 지난 버전 폴더는 고치지 않으므로(AGENTS) 바뀌는 결정을 여기 모아 둔다.

**배제한 대안**

- **v0.1 결정을 모두 옮겨 적기** — 같은 내용이 두 곳에 생긴다. 배제.

## D-2. 위키 페이지는 wiki/<분야>/<소스>/에 두고, 소스는 youtube·docs·web이다

> D-10으로 개정: 소스는 youtube·web 두 개다.

**선택**

```text
wiki/<분야>/
  index.md
  youtube/<페이지>.md     유튜브 영상에서 만든 페이지
  docs/<페이지>.md        사람이 넣은 마크다운 문서에서 만든 페이지
  web/<페이지>.md         외부 웹 검색으로 만든 페이지, 또는 소스가 둘 이상 섞인 페이지
```

소스 폴더도 분야 폴더처럼 미리 만들지 않고, 그 소스의 첫 페이지를 저장할 때 만든다. 페이지 파일 이름은 v0.1 D-2대로 영문 소문자·숫자·하이픈이고 날짜를 붙이지 않는다.

**근거**

사용자 지시 "위키는 wiki\{분야}로 나누고 하위 폴더는 자료의 소스로 나누고 싶습니다. 즉, dev\youtube가 추가되어야 합니다." 사용자 답 "youtube · docs · web".

**배제한 대안**

- **youtube·docs 두 개** — 사용자가 고르지 않았다. 배제.
- **원본 폴더별 하위 폴더** — 사용자가 고르지 않았다. 배제.

---

## D-3. 소스가 하나면 그 소스 폴더에, 둘 이상이면 web에 두고, 나중에 섞이면 web으로 옮긴다

> D-10으로 개정: docs가 없어져 "유튜브만이면 youtube, 그 밖에는 web"이 된다.

**선택**

- 페이지의 `sources`가 한 소스에서만 왔으면 그 소스 폴더에 둔다.
- 둘 이상의 소스가 섞였으면 `web/`에 둔다. 직접 겪은 일(v0.1 D-17의 저장소 안 기록 문서)은 소스 종류를 늘리지 않는다.
- 이미 있는 페이지에 다른 소스의 내용을 보태 섞이게 되면, 같은 커밋에서 페이지를 `web/`으로 옮기고 그 페이지를 가리키는 링크와 분야 index를 함께 고친다.

**근거**

사용자 답 "web으로 해 주세요"(섞인 페이지), "옮김 (규칙 그대로)"(나중에 섞일 때).

**배제한 대안**

- **혼합용 폴더 따로** — 사용자가 web을 골랐다. 배제.
- **처음 위치 유지** — 링크가 깨지지 않지만 사용자가 규칙대로 옮기기를 골랐다. 배제.

---

## D-4. inbox·raw의 원본 폴더 이름은 YYMMDD-{소스}-{title}이다

> D-10으로 개정: {소스}는 youtube 또는 web이다.

**선택**

- 형식: `YYMMDD-{소스}-{title-in-kebab-case}`. 예) `261101-docs-rust-gui`, `261101-youtube-claude-skill-writing-rules`
- `YYMMDD`: 원본을 inbox에 넣은 날. raw로 옮겨도 바꾸지 않는다.
- `{소스}`: `youtube` 또는 `docs`. 외부 웹 검색 자료는 원본을 두지 않으므로(v0.1 D-4) `web`인 원본 폴더는 없다.
- `{title}`: 넣는 사람이 짓는다. 규칙과 다른 이름으로 들어오면 에이전트가 원래 폴더 이름이나 제목으로 새 이름을 제안하고 확인받아 바꾼다.
- 유튜브의 `{title}`은 영상 제목을 영문으로 요약한 것이다. 영상 ID는 폴더 안 파일 이름(`<영상ID>.meta.json` 등)에 남는다.
- 원본 하나가 파일 하나여도 폴더로 둔다.
- 폴더 안의 파일 이름은 바꾸지 않는다(v0.1 D-2·D-16).

**근거**

사용자 지시 "inbox, raw의 폴더명 규칙 재정의: YYMMDD-{소스}-{title-in-kebab-case}". 사용자 답 "inbox에 넣은 날", "넣는 사람이, 없으면 에이전트", "영상 제목 영문 요약".

**배제한 대안**

- **원본이 만들어진 날, 정리한 날** — 사용자가 고르지 않았다. 배제.
- **항상 에이전트가 제안** — 사용자가 고르지 않았다. 배제.
- **유튜브 title을 영상 ID로** — 사용자가 고르지 않았다. 배제.

## D-5. raw는 raw/<분야>/<원본 폴더>/이고, 이 규칙에 맞출 때만 폴더 이름·위치를 바꿀 수 있다

> D-9로 개정: raw도 소스로 나눈다. D-12로 다시 개정: raw는 분야로 나누지 않고 raw/{소스}/YYMMDD-{title}이다.

**선택**

원본은 정리 후 `raw/<분야>/<YYMMDD-소스-title>/`에 둔다. 소스 하위 폴더는 두지 않는다(폴더 이름에 소스가 있다). 원본 파일의 내용과 이름은 그대로 두고, 폴더 이름과 위치만 이 규칙에 맞추려고 바꿀 수 있다.

**근거**

사용자 답 "raw/<분야>/<이름>/". v0.1 D-3 "옮긴 뒤로는 고치지 않는다"는 파일 내용을 지키려는 것이고, 폴더 이름 변경(`git mv`)은 내용을 바꾸지 않는다.

**배제한 대안**

- **raw/<이름>/ 평평하게** — 사용자가 고르지 않았다. 배제.

## D-6. 목차는 분야 index 하나에 소스별 제목을 둔다

> D-10으로 개정: 제목은 youtube·web 두 개다.

**선택**

`wiki/<분야>/index.md` 하나에 `## youtube`, `## docs`, `## web` 제목을 두고 그 아래에 페이지를 한 줄씩 링크한다. 페이지가 없는 소스의 제목은 두지 않는다. 소스 폴더에는 index를 두지 않는다. `wiki/index.md`는 v0.1 D-7대로 분야 목록이다.

**근거**

사용자 답 "분야 index 하나, 소스별 제목".

**배제한 대안**

- **소스마다 index** — 목차가 3단이 된다. 사용자가 고르지 않았다. 배제.

**근거**

**배제한 대안**

- **apps 남겨 두기** — 사용자가 고르지 않았다. 배제.

## D-9. raw도 분야 아래를 소스로 나눈다 (D-5 개정)

> D-12로 개정: raw는 분야로 나누지 않는다. 최종 위치는 D-12 표에 있다.

**선택**

정리한 원본은 `raw/<분야>/<소스>/<YYMMDD-소스-title>/`에 둔다. 소스 폴더는 D-10의 `youtube`·`web`이다. 소스 폴더는 그 소스의 첫 원본을 옮길 때 만든다. 원본 폴더 이름은 D-4대로 소스를 그대로 담는다(inbox에는 소스 폴더가 없어서 이름에 소스가 필요하다). D-5의 "소스 하위 폴더는 두지 않는다"는 이 결정으로 바뀐다. 나머지(파일 내용·이름 불변, 폴더 이름·위치만 규칙에 맞출 때 변경 허용)는 D-5 그대로다. 지금 원본의 새 위치는 D-10 표에 있다.

**근거**

사용자 지시 "raw 폴더도 분야\소스로 구분"(2026-11-01, Phase 4 판정 뒤 버전 종료 전). 위키(D-2)와 같은 모양이 된다.

**배제한 대안**

- **D-5 그대로(raw/<분야>/<폴더>/)** — 사용자가 바꾸기로 했다. 배제.
- **소스 폴더로 나누면서 폴더 이름에서 소스를 빼기** — inbox에는 소스 폴더가 없어 이름에 소스가 필요하고, raw로 옮길 때 이름을 바꾸지 않는 편이 단순하다. 사용자가 지시하지 않았다. 배제.

## D-10. 소스는 web·youtube 두 개다. docs를 없애고 web으로 바꾼다 (D-2·D-3·D-4 개정)

**선택**

- 소스는 `youtube`(유튜브 영상의 자막·요약)와 `web`(웹에서 가져온 정보) 두 개다. 노트북에서 넣은 마크다운 문서도 웹 정보를 AI 에이전트가 정리한 것이므로 `web`이다.
- `web` 원본(에이전트가 정리한 문서 폴더)은 inbox에 `YYMMDD-web-{title}`로 들어와 `raw/<분야>/web/`에 보관한다. 질문에 답하며 한 웹 검색 결과는 v0.1 D-4대로 원본을 두지 않고 URL만 `sources`에 남긴다.
- 페이지 위치(D-3): 유튜브만이면 `youtube/`, 웹 정보만이거나 두 소스가 섞이면 `web/`. `youtube/` 페이지에 웹 내용을 보태면 `web/`으로 옮긴다.
- 분야 index(D-6)의 제목은 `## youtube`·`## web` 두 개다.

지금 원본·페이지의 새 이름과 위치:

| 지금 | 새 이름·위치 |
| --- | --- |
| `raw/dev/261101-docs-herdr/` | `raw/dev/web/261101-web-herdr/` |
| `raw/dev/261101-docs-rust-gui/` | `raw/dev/web/261101-web-rust-gui/` |
| `raw/dev/261101-docs-ego-lite-guide/` | `raw/dev/web/261101-web-ego-lite-guide/` |
| `raw/dev/261101-docs-ssh-tailscale-remote-terminal-guide/` | `raw/dev/web/261101-web-ssh-tailscale-remote-terminal-guide/` |
| `raw/dev/261101-youtube-claude-skill-writing-rules/` | `raw/dev/youtube/261101-youtube-claude-skill-writing-rules/` |
| `wiki/dev/docs/*.md` (4개) | `wiki/dev/web/` |

**근거**

사용자 지시 "docs 소스도 웹에서 가져온 정보를 AI 에이전트가 정리한 것입니다. docs 소스를 제거하고 web으로 변경. 즉, 소스는 web, youtube 2개입니다."(2026-11-01, D-9 작업 중).

**배제한 대안**

- **docs·web·youtube 셋 유지** — 사용자가 docs를 없애기로 했다. 배제.

## D-11. 유튜브 페이지는 주제 단위로 두고, 안을 영상별 섹션(등록일·최신순)으로 나눈다

**선택**

- 유튜브 페이지는 v0.1 D-11대로 주제 단위다. 영상 하나에 페이지 하나가 아니다.
- 페이지 안은 영상마다 `## YYYY-MM-DD · <영상 제목>` 섹션 하나로 나누고, **최신 등록일이 위**로 오게 둔다. 섹션 안에 채널·길이·URL·원본 raw 링크를 두고, 그 영상에서 정리한 내용은 `###` 하위 절로 쓴다(타임스탬프 유지).
- 등록일은 그 영상 `<영상ID>.meta.json`의 `upload_date`(YYYYMMDD)를 `YYYY-MM-DD`로 쓴다. 원본 폴더 이름의 날짜(inbox에 넣은 날)와 다르다.
- 페이지 맨 위에는 최신 영상 기준의 요약과(있으면) `## 점검 목록 (최신 기준)`을 두고, 새 영상이 들어올 때마다 고친다.
- 나중 영상이 예전 영상과 내용이 다르면 둘 다 두고, 최신 섹션에 `> YYYY-MM-DD 영상과 다름: …`을 적는다. 다른 내용을 넣기 전에는 v0.1 D-11대로 묻는다.
- 웹 내용을 보태 `web/`으로 옮긴 페이지도 영상 섹션 양식은 유지한다.

**근거**

사용자 답 "지금 규칙 그대로 적용"(주제 단위). 사용자 지시 "유튜브는 최신 정보가 중요하므로 문서의 섹션별로 유튜브의 등록일이 포함되고, 문서에 최신 정보 순으로 정의되는 것이 좋겠습니다." 사용자 답 "영상별 섹션", "둘 다 두고 최신에 표시"(2026-11-01).

**배제한 대안**

## D-12. inbox는 YYMMDD-{소스}-{title}, raw는 raw/{소스}/YYMMDD-{title}이고 raw는 분야로 나누지 않는다 (D-4·D-5·D-9 개정)

**선택**

- inbox: `inbox/YYMMDD-{소스}-{title-in-english}/` (D-4 그대로).
- raw: `raw/{소스}/YYMMDD-{title-in-english}/`. raw는 분야로 나누지 않는다. 소스는 상위 폴더에 있으므로 폴더 이름에서 뺀다.
- inbox에서 raw로 옮길 때 이름에서 `-{소스}`만 빼고 날짜·title은 그대로 둔다. 폴더 안의 구조·파일 이름·내용은 바꾸지 않는다(D-5 그대로).
- `{title-in-english}`는 영문 소문자·숫자·하이픈(kebab-case)이다. `YYMMDD`는 6자리를 유지한다.
- 원본의 분야는 그 원본을 `sources`로 가리키는 위키 페이지의 위치로 알 수 있다.

**근거**

사용자 지시 "inbox의 폴더 규칙: inbox\YYYYMMDD-{소스}-{titile-in-english}, raw의 폴더 규칙: raw\{소스}\YYYMMDD-{titile-in-english}", 이어서 "날짜 접두사를 YYMMDD로 유지"(2026-11-01). `YYYMMDD`는 오타로 보고 날짜 형식은 YYMMDD로 맞췄다.
