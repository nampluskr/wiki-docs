# Rust 동영상 플레이어 구현 가이드 — 독립 조사 sol

1. 권고: 두 UI에 공통 `PlayerSession`을 두고 libmpv로 재생·동기화·자막·트랙·R1을 맡긴다. Windows 초기 출력은 탭 전용 자식 HWND + `wid`가 현실적이다. [mpv](https://mpv.io/manual/stable/#embedding-into-other-programs-libmpv)
2. gpui의 이미지 API는 빠른 기능 검증에 적합하나 Windows에서 GPU 디코딩 표면을 그대로 받는 공개 `paint_surface` 경로로 간주하면 안 된다. [gpui-pre Window](https://docs.rs/gpui-pre/0.3.10/gpui/struct.Window.html)
3. mpv D3D11 render API는 2026-10-15 master에 추가됐다. 최신 정식 0.41.0과 구분해야 한다. [추가 커밋](https://github.com/mpv-player/mpv/commit/4255130de410e0cbdab694b951085409d466b704), [정식 릴리스](https://github.com/mpv-player/mpv/releases/tag/v0.41.0)
4. Tauri의 일반 `<video>`만으로 지정된 범용 재생·명시적 R1·전체 R2를 보장할 수 없다. [Windows 코덱](https://github.com/MicrosoftDocs/windows-dev-docs/blob/docs/hub/apps/develop/media-authoring-processing/supported-codecs.md), [WebCodecs](https://www.w3.org/TR/webcodecs/#hardware-acceleration)
5. R2 구현이 가장 쉬운 것은 mpv 속성 + lavfi 필터지만, `hqdn3d`·`eq`의 GPL 및 GPU→CPU 복사를 고려해야 한다. [FFmpeg configure](https://github.com/FFmpeg/FFmpeg/blob/master/configure), [mpv vf](https://mpv.io/manual/stable/#video-filters)
6. Windows에서는 D3D11VA를 우선 평가하고 실제 사용 모드는 `hwdec-current`로 표시한다. ON 요청과 실제 하드웨어 사용은 다른 상태다. [mpv hwdec](https://mpv.io/manual/stable/#options-hwdec), [상태](https://mpv.io/manual/stable/#property-list)
7. 현재 gpui 저장소는 고정 탭·활성 아이템 자리, Tauri는 `App.tsx` placeholder다. 완성된 pane-item 플러그인 구조가 이미 있다는 전제는 틀리다. [gpui 로컬 소스](D:/projects/workbench-gpui/src/ui/mod.rs), [Tauri 로컬 소스](D:/projects/workbench-tauri/src/App.tsx)
8. 4K60 BGRA 전송은 원시 데이터만 약 1.99 GB/s다. 프레임 IPC·매번 이미지 생성·CPU 필터가 병목 후보이며 무복사와 GPU 내부 복사는 구별한다. [직접 계산 근거: RenderImage 바이트 API](https://docs.rs/gpui-pre/0.3.10/gpui/struct.RenderImage.html)
9. 숨김 탭은 기본 일시정지, 분할은 가시 세션만 출력, 여러 탭 동시 재생은 명시적 선택으로 제한하는 설계를 권한다. [설계 근거: mpv pause·영상 출력 제어](https://mpv.io/manual/stable/#property-list)
10. 설치·빌드·설정 변경 없이 조사했으며, 버전·별·커밋 확인일은 모두 2026-11-01 KST다. 이 문서는 실측 성능 또는 동작 보증이 아니다.

확인 범위: crates.io API의 `max_stable_version`에 대응하는 버전과 `created_at`을 사용했다. prerelease, Git HEAD, README 예제 버전은 별도로 구분한다. 릴리스 날짜는 API UTC 날짜다. 유지 상태 판단은 명시된 유지 정책 또는 릴리스/커밋에 근거한 **평가**다. 로컬 저장소는 읽기만 했고 다른 scouter 산출물은 열지 않았다. 아래의 **설계 제안/추정**은 검증된 제품 동작과 구분한다. [crates.io API 예](https://crates.io/api/v1/crates/ffmpeg-next)

## Q1 권장안

- **gpui 1안 — 가장 빨리 요구 기능 달성:** `libmpv2` + libmpv/FFmpeg/libass + WASAPI + 탭별 전용 자식 HWND. `vo=gpu-next`, Windows 출력은 D3D11 컨텍스트, `hwdec=auto` 또는 `d3d11va,auto`를 검증 후 고정한다. mpv가 demux·탐색·속도·다중 트랙·자막·동기화를 이미 갖추므로 직접 FFmpeg 플레이어를 만드는 것보다 구현량이 적다는 **평가**다. 범용 지원은 포함된 FFmpeg 빌드에 달린다. [mpv 옵션](https://mpv.io/manual/stable/), [libmpv2](https://github.com/kohsine/libmpv-rs)
- **gpui 2안 — 편집기 같은 합성 완성도:** libmpv D3D11 render API로 앱 소유 텍스처에 출력하고 gpui D3D11 renderer에 외부 텍스처 합성 경로를 추가한다. 이는 **통합 개발 제안**이며 현재 gpui 공개 이미지 API만으로 완료되는 조합은 아니다. master 기능·FFI 추가·gpui renderer 변경을 수용할 때 검토한다. [mpv D3D11 계약](https://github.com/mpv-player/mpv/blob/master/include/mpv/render_d3d11.h), [gpui renderer](https://github.com/zed-industries/zed/blob/main/crates/gpui_windows/src/directx_renderer.rs)
- **gpui 3안 — 순수 UI 내부 PoC:** GStreamer appsink → BGRA → `RenderImage` → `img`를 사용한다. `gpui-video-player`의 Windows 경로가 참고 사례다. GPU 디코딩을 사용해도 최종 CPU 프레임 회수가 있으면 무복사가 아니다. 4K60 주력 경로로 채택하기 전 실측이 필요하다. [사례의 플랫폼 설명](https://github.com/cijiugechu/gpui-video-player#platform-notes)
- **Tauri 권고:** Rust 측 동일 libmpv 엔진 + 네이티브 영상 표면, WebView에는 제어·위치·상태만 IPC로 전달. 초기에는 HWND, DOM 오버레이가 필수면 ANGLE render API + 투명 WebView를 검토한다. Cathode는 후자의 실제 사례다. [Cathode](https://github.com/kaiserbh/cathode), [Tauri IPC](https://v2.tauri.app/concept/inter-process-communication/)
- **일반 `<video>` 판정:** MP4/H.264/AAC 같은 제한된 입력에는 유용하나 MKV/TS·HEVC·AC3·ASS·강제 R1 전환·시간축 기반 필터 전체의 공통 보장이 없다. 파일 확장자·컨테이너·코덱·프로파일을 따로 검사해야 한다. WebCodecs의 hardwareAcceleration도 강제 명령이 아닌 힌트다. [Windows 지원 목록](https://github.com/MicrosoftDocs/windows-dev-docs/blob/docs/hub/apps/develop/media-authoring-processing/supported-codecs.md), [W3C](https://www.w3.org/TR/webcodecs/#hardware-acceleration), [HTML media 계약](https://html.spec.whatwg.org/multipage/media.html)
- **R1·R2 최단 경로:** libmpv 속성 제어 + `vf`/lavfi 필터. GPL 배포를 허용하지 않는다면 밝기·대비·채도는 mpv 출력 속성, sharpen/blur/denoise는 라이선스를 확인한 사용자 셰이더 또는 LGPL 필터로 대체하고 성능을 재평가한다. [mpv 필터와 equalizer](https://mpv.io/manual/stable/), [FFmpeg 법률 안내](https://ffmpeg.org/legal.html)

## Q2 파이프라인 구조

- **직접 구현 시 제안 구조:** 입력 I/O·demux → 유한 packet queue → 오디오/비디오 decoder → filter → 유한 PCM/frame queue → WASAPI/영상 presenter. UI 스레드에는 명령과 상태 스냅샷만 보낸다. libmpv/GStreamer 선택 시 이 내부 구조를 중복 구현하지 않는다. [FFmpeg decode API](https://ffmpeg.org/doxygen/trunk/group__lavc__encdec.html), [GStreamer 실행 모델](https://gstreamer.freedesktop.org/documentation/application-development/advanced/threads.html)
- **스레드 제안:** UI, session control/event pump, blocking I/O·demux, decode/filter, render, audio callback을 역할로 분리하되 엔진 자체 스레드를 존중한다. libmpv render callback 안에서는 UI나 일반 mpv 명령을 동기 호출하지 않고 깨우기 신호만 보낸다. render 스레드와 core의 상호 대기는 데드록 위험이다. [libmpv threading](https://github.com/mpv-player/mpv/blob/master/include/mpv/render.h)
- **버퍼 제안:** 로컬 파일은 수 프레임 및 수백 ms 수준에서 시작해 조정하고 메모리·시간 상한을 모두 둔다. 4K BGRA 1장은 33.18 MB이므로 30장 큐만 약 995 MB다(**산술값**, 앱 전체 사용량 아님). packet queue의 GOP 의존성과 frame queue를 구별한다. [RenderImage](https://docs.rs/gpui-pre/0.3.10/gpui/struct.RenderImage.html), [GStreamer queue 한계](https://gstreamer.freedesktop.org/documentation/coreelements/queue.html)
- **상태 기계 제안:** Closed → Opening → Buffering → Playing ↔ Paused → Seeking → Playing/Paused → Ended; Error·Recovering·Closing은 별도 상태. seek·파일 교체·R1 교체에는 generation 번호를 증가시켜 이전 큐 결과를 버린다. 필터 설정/요청 hwdec/실제 hwdec는 독립 상태로 둔다. [비교할 실제 상태 모델: alhazen-core](https://github.com/alhazen-rs/alhazen-core#events-and-state), [mpv events](https://github.com/mpv-player/mpv/blob/master/include/mpv/client.h)
- **A/V 동기화:** 일반 파일 재생은 실제 출력 중인 오디오의 PTS·device latency를 기준 시계로 삼고 비디오 PTS를 그 시계에 맞춘다. 늦은 표시 프레임은 버리고 이른 프레임은 대기한다. PTS는 time_base로 환산하며 DTS나 frame index를 표시 시각으로 대체하지 않는다. 오디오 없는 파일은 monotonic clock을 쓰는 설계를 권한다. [GStreamer clocks](https://gstreamer.freedesktop.org/documentation/application-development/advanced/clocks.html), [FFmpeg AVFrame](https://ffmpeg.org/doxygen/trunk/structAVFrame.html), [mpv video-sync](https://mpv.io/manual/stable/#options-video-sync)
- **속도 변경:** media time과 wall time의 배율 및 오디오 time stretch를 같이 바꾼다. 단순 프레임 sleep 변경만으로는 음성이 맞지 않는다. mpv `speed`·`audio-pitch-correction` 사용이 쉽고, 직접 구현은 resample과 pitch-preserving stretch를 구분해야 한다. [mpv speed](https://mpv.io/manual/stable/#options-speed), [FFmpeg atempo](https://ffmpeg.org/ffmpeg-filters.html#atempo)
- **탐색:** 빠른 seek는 가까운 키프레임으로 이동, 정확 seek는 앞 키프레임으로 간 뒤 목표 PTS까지 decode/discard한다. decoder·filter·audio/frame queue를 flush하고 오디오 시계를 새 위치로 재기준화한다. 슬라이더 drag는 keyframe seek를 묶어서 보내고 release에서 exact를 제안한다. mpv `seek`의 `keyframes`/`exact`와 `hr-seek`가 대응한다. [mpv seek](https://mpv.io/manual/stable/#command-interface-seek), [FFmpeg seek/flush](https://ffmpeg.org/doxygen/trunk/group__lavf__decoding.html)

- **D3D11VA vs DXVA2:** 새 Windows D3D11 출력에는 D3D11VA 우선, DXVA2는 구형 경로 호환 옵션으로 둔다. GPU별 지원 codec/profile/bit depth/해상도를 실제 probe한다. GPU가 있다고 모든 HEVC 4:4:4·10-bit H.264가 되는 것은 아니다. [mpv HW 목록](https://mpv.io/manual/stable/#options-hwdec), [D3D11 decoder profile](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11videodevice-getvideodecoderprofile)
- **NVDEC/QSV:** 각각 NVIDIA·Intel 전용 경로이며 Windows의 벤더 중립 D3D11VA와 구분한다. FFmpeg QSV는 oneVPL/MFX device 경로, NVIDIA는 CUDA/NVDEC interop가 관여한다. encoder인 NVENC/QSV encode 존재를 decode 성공 증거로 쓰지 않는다. 기본 제품 UI는 GPU API 목록보다 ON/OFF + 실제 엔진 표시를 권한다. [FFmpeg HW 문서](https://ffmpeg.org/ffmpeg-doc.html#Advanced-Video-options), [mpv NVDEC](https://mpv.io/manual/stable/#options-hwdec), [Intel oneVPL](https://github.com/intel/libvpl)
- **자동 전환 설계:** initialization 실패·decode error·device removed를 분리한다. 정상적인 unsupported codec는 SW 재시작, device loss는 presenter까지 재생성, 반복 실패는 해당 세션 HW 재시도를 제한한다. 재생 위치·pause·선택 트랙·필터를 보존하고 사용자에게 실제 SW 상태를 보여준다. 드라이버 crash까지 엔진이 모두 복구한다고 보장하지 않는다. [mpv 주의사항](https://mpv.io/manual/stable/#options-hwdec), [D3D device removed](https://learn.microsoft.com/en-us/windows/win32/direct3d11/overviews-direct3d-11-devices-initialize)
- **무복사 정의:** decoder surface가 CPU readback 없이 같은 GPU 출력 파이프라인으로 넘어가야 한다. device/adapter 공유·texture 형식·동기화·자막 합성이 필요하며 GPU 내부 blit가 있어도 CPU 무복사라는 표현은 가능하다. “copy 0회”와 혼용하지 않는다. mpv 새 D3D11 API는 동일 device texture를 요구하고 다른 device 접근에는 동기화가 필요하다. [render_d3d11.h](https://github.com/mpv-player/mpv/blob/master/include/mpv/render_d3d11.h)

| 흐리게 | `gblur` sigma·steps; unsharp 음수도 blur 용도 | lavfi gblur, 사용자 shader | separable Gaussian 2-pass 등. radius에 따라 fetch·중간 texture 비용 증가(**알고리즘 평가**) | [gblur](https://ffmpeg.org/ffmpeg-filters.html#gblur), [libplacebo shader](https://libplacebo.org/custom-shaders/) |
| 노이즈 제거 | `hqdn3d` spatial/temporal, `nlmeans` strength·patch/search | lavfi 필터, 또는 검증된 denoise shader | 단순 blur가 denoise와 동등하지 않음. 시간축 denoise는 이전 프레임과 motion/잔상 처리가 필요 | [hqdn3d](https://ffmpeg.org/ffmpeg-filters.html#hqdn3d), [nlmeans](https://ffmpeg.org/ffmpeg-filters.html#nlmeans) |
| 디인터레이스 | `yadif`/`bwdif` mode/parity/deint | `deinterlace=yes/no` + 실제 graph 확인, 명시 lavfi 가능 | GStreamer `d3d11deinterlace`는 D3D11 VideoProcessor 사용. 단일 프레임 후처리로 motion-adaptive와 같은 결과를 보장 못 함 | [bwdif](https://ffmpeg.org/ffmpeg-filters.html#bwdif), [mpv](https://mpv.io/manual/stable/#options-deinterlace), [GStreamer](https://gstreamer.freedesktop.org/documentation/d3d11/d3d11deinterlace.html) |
| 밝기·대비·채도 | `eq` 또는 별도 color shader | `brightness/contrast/saturation` 속성 -100..100 | mpv 출력 변환·shader uniform, D3D11 VideoProcessor 해당 filter가 지원될 때 가능 | [mpv equalizer](https://mpv.io/manual/stable/#equalizer), [D3D enum](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ne-d3d11-d3d11_video_processor_filter) |

- **실시간 제어:** mpv equalizer 속성은 set_property, 필터는 label을 붙인 `vf add/remove/toggle/set`·`vf-command`로 관리한다. FFmpeg 직접 구현은 filter별 runtime command 지원을 검사하고 미지원 옵션은 안전한 graph rebuild를 한다. `gblur`·`hqdn3d`는 runtime param/command 구현이 있지만 모든 필터·옵션이 그런 것은 아니다. [mpv commands](https://mpv.io/manual/stable/#command-interface), [gblur 구현](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_gblur.c), [hqdn3d 구현](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_hqdn3d.c)
- **UI 제안:** ON/OFF와 strength를 분리 저장하고 OFF에서 마지막 강도를 보존한다. slider 입력은 합치고 매 마우스 이벤트마다 pipeline을 재생성하지 않는다. 적용 실패 시 이전 유효 graph로 복귀하며 pause 상태에서도 변경된 프레임을 다시 출력한다. 시간축 필터는 seek·트랙 교체·필터 topology 변경 시 이력을 초기화한다. [filtergraph 제어 근거](https://ffmpeg.org/ffmpeg-filters.html#Changing-options-at-runtime-with-a-command), [mpv filter labels](https://mpv.io/manual/stable/#video-filters)
- **GPU 셰이더:** gpui의 외부 D3D11 통합을 한다면 HLSL, 별도 wgpu renderer라면 WGSL로 sharpen/blur/color를 구현한다. mpv는 `glsl-shaders`와 libplacebo 기반 `vo=gpu-next`를 쓸 수 있다. WGSL·HLSL·mpv hook shader는 그대로 호환되는 파일 형식이 아니다. [WGSL](https://www.w3.org/TR/WGSL/), [HLSL](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl), [libplacebo](https://libplacebo.org/custom-shaders/), [mpv shaders](https://mpv.io/manual/stable/#options-glsl-shaders)
- **D3D11 video processor:** brightness/contrast/hue/saturation/noise reduction/edge enhancement enum이 있으나 지원 caps와 GetVideoProcessorFilterRange 결과를 조회해야 한다. enum 존재만으로 모든 GPU에서 R2를 충족하지 않는다. 일반 Gaussian blur를 직접 대신하는 표준 enum도 없다. denoise·edge enhancement 강도/품질은 드라이버에 따라 달라질 수 있어 shader/CPU fallback을 권한다. [filter enum](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ne-d3d11-d3d11_video_processor_filter), [range](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11videoprocessorenumerator-getvideoprocessorfilterrange)
- **CPU 대 GPU 평가:** 단순 공간·색 필터는 GPU에 유지하면 readback을 줄일 수 있다. nlmeans의 탐색·temporal denoise는 비용이 크고 품질은 파라미터/구현에 달린다. HW decode + CPU `hqdn3d`는 다운로드·재업로드가 생길 수 있으며 ON이 항상 빨라지는 것은 아니다. 4K60 품질 프리셋별 성능은 **미확인**이다. [FFmpeg HW sample](https://ffmpeg.org/doxygen/8.1/hw_decode_8c-example.html), [nlmeans](https://ffmpeg.org/ffmpeg-filters.html#nlmeans)
- **라이선스 함정:** 현재 FFmpeg configure에 `hqdn3d_filter_deps="gpl"`, `eq_filter_deps="gpl"`가 있다. unsharp/yadif/bwdif/nlmeans 파일은 LGPL 표기를 확인했다. `gblur` 파일은 다른 허용적 고지를 사용하므로 모든 필터를 같은 라이선스로 뭉뚱그리지 않는다. 최종 구성 전체를 기준으로 판단한다. [configure](https://github.com/FFmpeg/FFmpeg/blob/master/configure), [unsharp](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_unsharp.c), [bwdif](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_bwdif.c), [nlmeans](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_nlmeans.c), [gblur](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_gblur.c)

## Q9 소리 출력

- **mpv/GStreamer 권고:** 엔진의 WASAPI sink/ao를 사용하고 cpal/rodio로 오디오를 다시 꺼내 재생하지 않는다. clock·buffer·speed·device 변경 책임을 한 엔진에 두는 설계가 단순하다. mpv는 `audio-device-list`·`audio-device`를 제공한다. [mpv audio](https://mpv.io/manual/stable/#audio-output-drivers), [audio-device](https://mpv.io/manual/stable/#options-audio-device), [GStreamer wasapi2](https://gstreamer.freedesktop.org/documentation/wasapi2/index.html)
- **직접 FFmpeg 엔진:** cpal 0.18.2의 WASAPI output callback + 유한 PCM ring buffer를 권한다. callback 안의 decode·할당·파일 I/O·UI lock을 피하고 underrun은 silence/상태 보고로 처리한다. PCM 누적 샘플 수와 output timestamp/latency를 이용해 오디오 시계를 만든다. [cpal](https://docs.rs/cpal/0.18.2/cpal/), [StreamInstant](https://docs.rs/cpal/0.18.2/cpal/struct.StreamInstant.html)
- **rodio:** 출력·mixer·source·속도·변환을 고수준으로 제공해 오디오 PoC에 편하지만 영화의 PTS·seek flush·정확한 device clock은 앱 통합이 더 필요하다는 평가다. rodio가 영상 동기화 엔진은 아니다. [rodio docs](https://docs.rs/rodio/0.23.0/rodio/)
- **장치 변경:** 기본 장치 변경·USB 분리·Bluetooth 프로파일 변경을 별도 검사하고 필요하면 output stream을 다시 연 뒤 rate/channel layout·clock을 재설정한다. cpal 0.18.2 changelog는 WASAPI 기본 장치 변경의 잘못된 DeviceChanged 신호를 수정했다고 하므로 이전 온라인 설명의 자동 reroute를 맹신하면 안 된다. [cpal changelog](https://docs.rs/crate/cpal/0.18.2/source/CHANGELOG.md)
- **리샘플링:** decoder PCM rate와 출력 rate·channel layout이 다르면 libswresample 또는 적절한 Rust resampler로 변환하고 지연을 PTS에 반영한다. sample-rate conversion과 tempo/pitch 변경은 다른 기능이다. [libswresample](https://ffmpeg.org/libswresample.html), [atempo](https://ffmpeg.org/ffmpeg-filters.html#atempo)

## Q10 자막

- **권고:** mpv의 libass 경로로 외부 SRT/ASS와 내장 subtitle track을 처리하고 `sid`, `secondary-sid`, `sub-delay`, `sub-scale`, `sub-add`와 track-list를 UI에 연결한다. 실제 지원은 libass/FFmpeg 포함 빌드 및 subtitle 유형에 달린다. [mpv subtitles](https://mpv.io/manual/stable/#subtitles), [libass](https://github.com/libass/libass)
- **직접 구현:** SRT cue는 PTS 기준으로 표시할 수 있으나 ASS는 positioning·style·karaoke·font fallback·MKV font attachments까지 고려하므로 libass 사용이 실용적이라는 평가다. libass는 bitmap을 만들고 합성/색공간/alpha 처리는 출력 계층 책임이다. Rust `libass 0.2.0` wrapper는 오래되어 native libass API·빌드를 별도 검증한다. [libass API](https://github.com/libass/libass/blob/master/libass/ass.h), [Rust wrapper](https://github.com/tadeokondrak/libass-rs)
- **WebView:** HTML text track의 WebVTT 모델만으로 ASS 표현을 그대로 재현한다고 볼 수 없다. libass bitmap을 native video와 합성하거나 별도 검증된 ASS renderer를 넣는다. subtitle은 video filter 전/후 어디에 합성할지도 정해야 blur가 자막까지 번지는 문제를 피할 수 있다. [HTML tracks](https://html.spec.whatwg.org/multipage/media.html#text-tracks), [mpv blend-subtitles](https://mpv.io/manual/stable/#options-blend-subtitles)

## Q12 빌드·배포·라이선스

- **조사만 수행:** 아래는 향후 구현자용 안내이며 이 작업에서 패키지 설치·cargo build·시스템 환경 변경을 실행하지 않았다.
- **FFmpeg DLL:** 프로젝트는 공식 download 페이지에서 연결하는 Windows 빌드 제공자 또는 재현 가능한 자체 빌드를 사용한다. rsmpeg 공식 Windows 가이드는 vcpkg 및 BtbN shared builds 등을 설명한다. MSVC target·x64·FFmpeg ABI·headers/import lib·CRT·bindgen/clang 필요 조건을 한 세트로 고정한다. “DLL만 있으면 cargo가 알아서 연결”은 틀리다. [FFmpeg download](https://ffmpeg.org/download.html#build-windows), [rsmpeg Windows](https://github.com/larksuite/rsmpeg/blob/master/doc/windows.md), [ffmpeg-next build](https://github.com/zmwangx/rust-ffmpeg/wiki/Notes-on-building)
- **libmpv DLL:** mpv 공식 installation 페이지는 shinchiro 등의 Windows 빌드를 연결한다. 포함 기능·libmpv 제공 여부·GPL/LGPL·DLL 의존성·release/hash를 확인한다. MSVC linker에는 적절한 `.lib` import library가 필요할 수 있고 MinGW `.dll.a`를 같은 것으로 취급하지 않는다. Cathode는 generated mpv.lib와 libmpv/ANGLE DLL을 bundling하는 구체적 사례다. [공식 목록](https://mpv.io/installation/), [Cathode build](https://github.com/kaiserbh/cathode#building-from-source)
- **GStreamer:** 공식 MSVC x64 패키지와 Rust target을 맞추고 해당 배포의 pkg-config 경로를 사용한다. runtime/development 구성, plugin DLL과 plugin scanner 및 종속 DLL을 포함하고 필요한 codec plugin 집합을 명시한다. 최신 native stable은 확인 시 1.28.8이나 이 문서에서 native 릴리스 날짜는 **미확인**이다. [download](https://gstreamer.freedesktop.org/download/), [bindings install](https://github.com/GStreamer/gstreamer-rs#installation), [Windows deployment](https://gstreamer.freedesktop.org/documentation/deploying/windows.html)
- **Tauri 묶기:** externalBin은 실행형 sidecar, resource는 DLL 등 데이터의 번들 대상이다. DLL 로딩 위치를 명시하고 clean Windows에서 검색 경로·누락 의존성·서명·업데이트를 검증한다. WebView2 Evergreen 의존과 Fixed Runtime 동봉은 크기/버전 정책이 다르다. TextureStream 실험 기능은 별도 Runtime 고정 검토가 필요하다. [sidecars](https://v2.tauri.app/develop/sidecar/), [resources](https://v2.tauri.app/develop/resources/), [Windows installer](https://v2.tauri.app/distribute/windows-installer/), [TextureStream](https://github.com/get-air/tauri-video-plugin/blob/main/docs/windows.md)
- **크기:** 일반 수치 보장은 **미확인**. 참고로 Cathode README는 Windows libmpv DLL 약 112 MB, vendor download 약 47 MB를 적는다. 이것은 특정 artifact의 예이지 모든 mpv 배포 크기가 아니다. GStreamer 전체 package와 필요한 plugin만 묶은 크기도 다르다. [Cathode](https://github.com/kaiserbh/cathode#building-from-source), [GStreamer deployment](https://gstreamer.freedesktop.org/documentation/deploying/windows.html)
- **FFmpeg:** 기본은 LGPL-2.1-or-later 중심이며 `--enable-gpl`로 GPL 부분을 포함하면 전체 라이브러리 구성의 조건이 달라진다. `--enable-nonfree`는 재배포 불가 구성에 주의한다. decode만 쓴다고 LGPL이 자동 보장되지 않으며 `eq`·`hqdn3d`도 GPL 요소다. LGPL dynamic linking도 고지·수정 라이브러리 교체·소스 제공 등 조건을 검토한다. [FFmpeg legal](https://ffmpeg.org/legal.html), [configure](https://github.com/FFmpeg/FFmpeg/blob/master/configure)
- **mpv:** 기본 전체는 GPLv2+, GPL-only 파일을 제외한 LGPL 구성 가능. `-Dgpl=false` 편의 옵션만으로 라이선스 허가가 자동 완성된다고 upstream도 말하지 않는다. `libmpv2` wrapper의 LGPL-2.1 표기와 실제 libmpv DLL/FFmpeg/libass closure의 조건은 따로 기록한다. [mpv Copyright](https://github.com/mpv-player/mpv/blob/master/Copyright), [wrapper metadata](https://crates.io/crates/libmpv2)
- **GStreamer/libass:** core는 LGPL 계열, plugin/외부 codec library별 조건은 별도다. bad/ugly 분류명은 곧 GPL이라는 뜻이 아니다. libass는 ISC이고 font·font shaping dependencies와 묶는 font 자체 권리도 확인한다. [GStreamer licensing](https://gstreamer.freedesktop.org/documentation/frequently-asked-questions/licensing.html), [libass license](https://github.com/libass/libass/blob/master/COPYING)
- **특허:** H.264/HEVC/AAC 등의 특허·상용 배포 의무는 오픈소스 라이선스와 별개다. OS decoder 사용 또는 외부 exe 분리만으로 제품의 특허/배포 문제가 모두 사라진다고 단정하지 않는다. 판매 국가·배포 방식별 판단은 이 조사에서 **미확인**이다. [FFmpeg patent FAQ](https://ffmpeg.org/legal.html)
- **코드 재사용:** 두 기반 저장소 INTENT/AGENTS는 Zed 앱 코드 복사 금지를 명시한다. 이 조사에는 GPL/LGPL 원문 코드를 수록하지 않았다. API 이름과 동작 분석만 적고 별도 앱의 구조를 설계한다. [gpui AGENTS](D:/projects/workbench-gpui/AGENTS.md), [Tauri AGENTS](D:/projects/workbench-tauri/AGENTS.md)

- **gpui 최신 main과 pinned pre:** 핵심 공개 이미지 API는 0.3.10 docs를 확인했지만 renderer 내부 변경을 pre 배포 원문 전체와 byte 단위 대조하지 않았다. main의 내부 위치·구현을 로컬 pinned crate 전체와 동일하다고 단정하지 않는다. [pinned docs](https://docs.rs/gpui-pre/0.3.10/gpui/), [upstream renderer](https://github.com/zed-industries/zed/blob/main/crates/gpui_windows/src/directx_renderer.rs)
- **ffmpeg-next 문서 불일치:** crates.io 9.0.0과 repo README의 지원 범위(3.4~8.0)가 일치하지 않는다. 특정 FFmpeg9 DLL과 MSVC에서의 build/link/run은 **미검증**이며 실제 선택 전 release별 bindings를 확인해야 한다. [API](https://crates.io/api/v1/crates/ffmpeg-next), [README](https://github.com/zmwangx/rust-ffmpeg)
- **Tauri plugin 안정성:** main의 0.4 예제와 published 0.3.0 차이 및 experimental WebView2 API는 확인했다. stable Runtime 지원 범위·rate/exact seek·R1/R2 exposure·배포 가능성은 **미확인**이다. [plugin](https://github.com/get-air/tauri-video-plugin), [API](https://crates.io/api/v1/crates/tauri-plugin-video), [Microsoft](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2experimentaltexturestream?view=webview2-1.0.4071-prerelease)
- **alhazen 주장과 OS:** README의 Windows AC3 “nothing to install” 같은 표현은 Windows24H2 공식 자료와 충돌할 수 있다. core 내부의 codec availability probe·오류 fallback·R1 runtime OFF·ASS·R2 전체를 직접 실행 검증하지 않았다. 신생 프로젝트의 장점을 유지하되 요구 충족 엔진으로 바로 채택하지 않는다. [alhazen](https://github.com/alhazen-rs/alhazen-core), [MS codec 표](https://github.com/MicrosoftDocs/windows-dev-docs/blob/docs/hub/apps/develop/media-authoring-processing/supported-codecs.md)
- **정확한 PotPlayer 대응:** 한국어 메뉴 문자열·현재 알고리즘·DXVA 기본값·강도별 동등 품질은 **미확인**이다. Q8은 기능 등가 설계표이며 사용자의 PotPlayer 설정을 그대로 복제한 표가 아니다. [공식 사이트](https://potplayer.daum.net/)
- **성능/전환 지연:** 4K60 대역폭 숫자는 산술값이다. 디코더 전환 중 음성 끊김·필터 재구성 지연·노트북 전력·GPU별 denoise 품질·동시 세션 수·최종 installer 크기는 모두 **미측정**이다.
