# YouTube 재생 R3 — 독립 조사 sol

1. R3 권고는 링크를 새 `PlayerSession` 탭에 넣고 libmpv 내장 ytdl_hook → 동봉 yt-dlp → 기존 디코딩·출력 경로로 재생하는 구조다. [mpv 0.41.0 옵션](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)
2. v0.41.0의 libmpv는 `config=no`지만 `ytdl=yes` 기본값은 유지한다. 사용자 스크립트 자동 로딩과 내장 hook 로딩은 별개다. [기본 profile](https://github.com/mpv-player/mpv/blob/v0.41.0/etc/builtin.conf), [scripting](https://github.com/mpv-player/mpv/blob/v0.41.0/player/scripting.c)
3. Lua 없는 libmpv 빌드에는 이 hook 경로가 없다. shinchiro 빌드 recipe는 Lua/LuaJIT를 활성화하지만 채택 DLL은 별도 확인한다. [mpv 옵션 조건](https://github.com/mpv-player/mpv/blob/v0.41.0/options/options.c), [recipe](https://github.com/shinchiro/mpv-winbuild-cmake/blob/0ee575368129b7656bde32532711c6d17906af6a/packages/mpv.cmake)
4. 2026-11-01 확인 최신 yt-dlp stable은 `2026.10.26`, nightly는 `2026.10.29.232701`이다. [stable API](https://api.github.com/repos/yt-dlp/yt-dlp/releases/latest), [nightly API](https://api.github.com/repos/yt-dlp/yt-dlp-nightly-builds/releases/latest)
5. 현재 완전한 YouTube 지원에는 EJS와 지원 JavaScript 런타임이 필요하다. 공식 exe는 EJS를 포함하지만 외부 런타임은 별도로 준비한다. [EJS 안내](https://github.com/yt-dlp/yt-dlp/wiki/EJS)
6. 4K VP9/AV1·분리 A/V는 format 선택 후 mpv가 EDL/개별 트랙으로 재생한다. 추출만 하는 이 경로에 외부 ffmpeg.exe 병합을 필수로 추가할 이유는 없다. [hook](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua)
7. R1·R2는 기존 libmpv 재생 경로를 공유하지만 GPU의 codec/profile 지원과 CPU 필터 readback 비용은 그대로 남는다. [hwdec·vf](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)
8. 시작·buffering·실패는 비동기 이벤트/속성으로 받고 `end-file redirect`와 오류를 구분한다. [client API](https://github.com/mpv-player/mpv/blob/v0.41.0/include/mpv/client.h)
9. 로그인·지역·봇 차단·쿠키 복호화·추출기 변경으로 재생이 실패할 수 있으며 계정/토큰/쿠키를 앱의 일반 로그에 남기지 않는 설계를 권한다. [yt-dlp YouTube 안내](https://github.com/yt-dlp/yt-dlp/wiki/Extractors#youtube)
10. 공식 IFrame 대안은 libmpv R1·R2를 제공하지 않으며, 개인 사용 허용 문구를 자동 추출·앱 배포에 대한 포괄 허가로 해석하지 않는다. [IFrame API](https://developers.google.com/youtube/iframe_api_reference), [YouTube 약관](https://www.youtube.com/t/terms?gl=GB)

확인일: **2026-11-01 KST**. 기준은 **mpv v0.41.0 tag의 문서·소스**와 확인일의 yt-dlp 공식 릴리스/문서다. 소스 동작 분석은 원문 코드 복사 없이 서술했다. 설치·빌드·설정 변경·실제 YouTube 재생·쿠키 접근은 하지 않았으며, 모든 동작 시험과 성능 수치는 **미검증**이다. 다른 scouter의 문서는 열지 않았다. 이 파일은 gpui·Tauri 묶음 A와 egui+glow 묶음 B가 함께 쓸 공통 문서의 재료이며, 최종 공통 문서는 수정하지 않았다.

## Y1 mpv 의 ytdl 연동

- **`--ytdl=yes/no`:** v0.41.0은 youtube-dl 호환 extractor를 호출하는 내장 hook를 활성화하며 기본 yes다. 이름은 ytdl이지만 YouTube 이외 사이트도 지원하며, 실제 지원은 외부 extractor 버전에 달린다. 앱은 YouTube 링크만 허용할지 별도 정책을 정한다. [0.41.0 옵션](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)
- **`ytdl_hook.lua`:** Lua 스크립트가 외부 yt-dlp 등을 subprocess로 실행하여 JSON을 받고 실제 영상·음성 URL, 자막, 제목, chapter 등을 mpv에 연결한다. YouTube 페이지 URL 자체를 FFmpeg decoder가 해석하는 구조가 아니다. [0.41.0 hook](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua)
- **실행 파일 검색:** 기본 후보는 `yt-dlp`, `yt-dlp_x86`, `youtube-dl`. `script-opts`의 `ytdl_hook-ytdl_path`로 절대 경로를 지정할 수 있고 Windows에서 여러 후보는 `;`로 구분한다. Windows는 `.exe` 실행형만 지원하며 suffix를 생략할 수 있다. 단순히 앱 EXE 옆에 놓으면 항상 찾는다고 가정하지 말고 절대 경로를 권한다. [문서](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst), [검색 구현](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua)
- **설정 예(코드가 아닌 옵션 값):** `ytdl=yes`, `script-opts=ytdl_hook-ytdl_path=C:/MyPlayer/tools/yt-dlp.exe`. libmpv option setter에는 옵션 이름 앞 `--`를 붙이지 않는다. 공백이 있는 경로는 shell 문자열로 조립하지 않고 API 값으로 전달한다. Windows `;`는 후보 구분자이므로 path escaping 정책도 확인한다. [옵션](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst), [libmpv setter](https://github.com/mpv-player/mpv/blob/v0.41.0/include/mpv/client.h)
- **선행 추출:** `ytdl_hook-try_ytdl_first=yes`는 먼저 extractor를 시도하게 한다. 기본은 no이지만 YouTube 도메인은 기본 include 패턴에 포함돼 우선 처리된다. 무조건 모든 URL에 강제로 추출기를 실행할 필요는 없다. [0.41.0 문서](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)
- **`--ytdl-format`:** 문자열을 extractor의 `--format`으로 전달한다. **0.41.0 기본은 빈 문자열**이고 빈 값/`ytdl`이면 format 인자를 전달하지 않아 extractor 기본 선택을 따른다. 옛 mpv의 default format 문자열을 0.41.0 기본값으로 인용하면 틀린다. [0.41.0 문서](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst), [기본값](https://github.com/mpv-player/mpv/blob/v0.41.0/options/options.c)
- **`--ytdl-raw-options`:** extractor 옵션 이름과 값을 key/value로 전달한다. flag는 값 없는 키가 아니라 빈 값 `=`를 붙인다. 예: `write-auto-subs=`, `ignore-config=`, `cookies-from-browser=edge`. mpv가 유효성 검사하지 않으므로 앱에서 허용 옵션과 조합을 제한하는 설계를 권한다. [문서](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst), [hook 인자 구성](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua)
- **쉼표 주의:** `script-opts`와 `ytdl-raw-options`는 key/value list다. `sub-langs=ko,en`을 단순 문자열로 넣으면 쉼표가 옵션 경계로 오해될 수 있으므로 mpv list escaping을 적용하거나 지원되는 native node/map 전달을 검증한다. `script-opts`는 전체 리스트를 대체하고 `script-opt`는 항목 추가라는 차이도 있다. [List Options·script-opts](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst), [node API](https://github.com/mpv-player/mpv/blob/v0.41.0/include/mpv/client.h)

- **Windows 빌드 확인:** shinchiro `packages/mpv.cmake`는 `luajit` 의존, `-Dlibmpv=true`, `-Dlua=enabled`를 명시하며 libmpv DLL을 dev package로 복사한다. 확인한 recipe의 최근 변경 커밋은 `0ee57536…`, 2026-08-04 UTC다. 따라서 **해당 recipe는 Lua 포함을 의도**하지만 모든 과거/변형 binary의 실제 feature를 보증하지 않는다. 실제 채택 DLL·hash·빌드 로그와 정상 URL smoke test는 **미확인**이다. [고정 recipe](https://github.com/shinchiro/mpv-winbuild-cmake/blob/0ee575368129b7656bde32532711c6d17906af6a/packages/mpv.cmake), [커밋 API](https://api.github.com/repos/shinchiro/mpv-winbuild-cmake/commits?path=packages/mpv.cmake&per_page=1), [mpv 공식 Windows 빌드 연결](https://mpv.io/installation/)
- **별도 설정 계층:** `config=no`는 mpv 설정을 격리할 뿐, subprocess yt-dlp의 사용자 config까지 자동 차단하는 옵션이 아니다. hook가 `--ignore-config`를 기본 넣지 않는 것을 확인했다. 앱이 동작을 통제하려면 `ytdl-raw-options=ignore-config=` 및 앱 관리 옵션을 제안한다. 임의 사용자 yt-dlp config의 출력/format/postprocess 옵션이 재생 추출에 섞이지 않도록 한다. [hook 인자](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua), [yt-dlp config](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#configuration)
- **Lua 미포함 대안:** 앱이 yt-dlp JSON을 별도로 받아 video/audio URL·headers·cookies·자막·manifest를 libmpv에 연결하는 resolver를 만들 수 있다. 다만 내장 hook가 하던 EDL·playlist·metadata·start 처리까지 다시 맡아야 하므로 단순 URL 1개 넘기는 것과 다르다는 **설계 평가**다. 초기 권고는 Lua 포함 libmpv + 내장 hook다. [hook 기능 범위](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua)

- **동봉 제안:** `tools/yt-dlp.exe`와 지원 Deno 실행형, 각 license notice·version·hash manifest를 앱 resource로 동봉하고 절대 경로를 설정한다. 추출기는 외부 프로세스이므로 Rust stable-msvc와 Python ABI를 연결할 필요는 없으나 architecture·OS 요구와 libmpv DLL의 ABI 배포는 각각 관리한다. Tauri는 sidecar/resource, gpui/egui는 자체 installer에 포함하는 설계를 권한다. [standalone 설명](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#release-files), [Tauri sidecar](https://v2.tauri.app/develop/sidecar/), [Tauri resources](https://v2.tauri.app/develop/resources/)
- **자체 갱신:** release binary의 `yt-dlp -U`는 현재 채널을 갱신한다. `--update-to nightly`는 채널 전환, `--update-to stable@2026.10.26` 같은 값은 버전 고정·복귀에 사용한다. 다른 저장소로 update-to도 가능하지만 upstream이 타 저장소 binary 검증 부재를 경고하므로 앱 updater는 공식 저장소만 허용하는 설계를 권한다. 이 조사에서는 실행하지 않았다. [Update](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#update)
- **앱 갱신 제안:** Program Files 안의 실행형에 무조건 `-U`를 실행하면 쓰기 권한·실행 중 교체·서명/installer 추적 문제가 생길 수 있다. 앱 업데이트에 함께 묶거나 사용자 writable versioned tools 폴더에 검증 후 새 버전을 놓고 다음 세션부터 전환하는 방식을 제안한다. 이전 버전을 남겨 회귀 시 rollback하고 동시 탭마다 중복 updater를 실행하지 않는다. 이는 **배포 설계 제안**, 검증된 yt-dlp 보장 기능은 아니다. [갱신 수단 근거](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#update)
- **빈번한 갱신 이유:** upstream은 사이트 변경으로 stable도 금방 깨질 수 있음을 명시한다. YouTube의 추출 응답·JS challenge·지원 client/format·PO token 요구 변경은 mpv를 바꾸지 않아도 resolver 갱신을 요구할 수 있다. 90일 이상 지난 yt-dlp에는 갱신 권고 경고도 있다. [Update](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#update), [EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS), [YouTube extractor 안내](https://github.com/yt-dlp/yt-dlp/wiki/Extractors#youtube)
- **최근 의존성 — EJS:** 완전한 YouTube 지원에는 challenge solver인 `yt-dlp-ejs`와 외부 JS runtime이 필요하다. 공식 standalone exe와 공식 zipimport 배포는 EJS를 포함한다. PyPI는 `[default]` dependency group 등 설치 방식에 따라 달라진다. EJS와 yt-dlp의 지원 버전도 함께 맞춰야 한다. **mpv의 Lua/MuJS는 이 외부 JS runtime을 대신하지 않는다**는 구조적 판단이다. [EJS 공식 안내](https://github.com/yt-dlp/yt-dlp/wiki/EJS), [Dependencies](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#dependencies)
- **JS runtime 조건:** 확인일 EJS 안내는 Deno **2.3.0+**(권장·기본 활성), Node **22.0.0+**(`--js-runtimes node` 명시), QuickJS/QuickJS-NG 등을 지원한다. Bun은 deprecated이며 **1.2.11~1.3.14**만 지원한다고 명시한다. 이 숫자는 **지원 최소/범위**이며 각 runtime의 최신 릴리스 번호는 **미확인**이다. [EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS)
- **Windows runtime 배치:** EJS 안내는 runtime이 PATH 또는 yt-dlp.exe와 같은 폴더에 있어도 된다고 한다. 더 명시적으로 `ytdl-raw-options`의 `js-runtimes=deno:C:/MyPlayer/tools/deno.exe`처럼 전달하는 구성을 검증할 수 있다. remote-components의 EJS 자동 다운로드도 있지만 동봉 공식 exe에는 기본적으로 EJS가 있어 추가 다운로드를 무조건 켤 필요는 없다. [EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS), [mpv raw-options](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)

## Y4 재생 설정

다음 format 문자열은 문서의 selector·filter 문법으로 구성한 **앱용 제안 예**다. 실제 제공 codec·해상도·접근 권한은 영상·지역·client·로그인 상태에 따라 달라지므로 전부 **미시험**이다. `+`는 A/V 선택 조합, `/`는 왼쪽 불가 시 대안, `height<=2160`은 4K 이하 상한이지 4K 보장이 아니다. [yt-dlp Format Selection](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#format-selection)

| UI 선택 | `ytdl-format` 값 예 | 의미·제약 | 근거 |
|---|---|---|---|
| 자동 | 빈 문자열 | extractor의 기본 선택. 앱 버전이 같아도 extractor 변경으로 선택 결과가 달라질 수 있음 | [mpv0.41](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst) |
| 4K 이하 자동 | `bv[height<=2160]+ba/b[height<=2160]` | video-only + audio, 없으면 muxed best; 4K 제공 보장 아님 | [selector](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#format-selection) |
| 4K 이하 VP9 고정 | `bv[height<=2160][vcodec^=vp9]+ba/b[height<=2160][vcodec^=vp9]` | VP9 prefix만. 없으면 format unavailable로 알려야 함 | [filter syntax](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#filtering-formats) |
| 4K 이하 AV1 고정 | `bv[height<=2160][vcodec^=av01]+ba/b[height<=2160][vcodec^=av01]` | yt-dlp codec 문자열 av01 prefix. 해당 format 없을 수 있음 | [filter syntax](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#filtering-formats), [mpv codec mapping](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua) |
| H.264 고정 | `bv[height<=2160][vcodec^=avc1]+ba/b[height<=2160][vcodec^=avc1]` | AVC 4K가 항상 존재한다고 보장하지 않음. 호환성 모드는 height<=1080 제한도 검토 | [filter syntax](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#filtering-formats), [mapping](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua) |

- **엄격 고정과 선호 구분:** VP9/AV1 앞에 우선순위를 두되 자동 대안을 원하면 `/bv[height<=2160]+ba/b[height<=2160]`를 뒤에 추가하는 구성을 제안한다. 이 경우 codec이 바뀔 수 있으므로 UI에는 “VP9 선호”로 표시하고 실제 `video-codec`/`hwdec-current`를 보여준다. `best` 하나를 최고 분리 스트림과 동일하게 취급하지 않는다. [format 대안 문법](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#format-selection), [mpv 속성](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/input.rst)
- **DASH 분리 스트림:** hook는 extractor `requested_formats`/`requested_downloads`를 읽고 video/audio를 EDL의 별도 media stream으로 연결한다. fragment형 DASH는 init segment와 조각 목록을 처리할 수 있고 `use_manifests=yes`면 가능한 manifest를 사용할 수 있다. **플레이어가 동기 재생하는 것**이며 먼저 단일 MP4로 다운로드·재인코딩하는 단계가 아니다. 별도의 ffmpeg.exe는 yt-dlp로 파일 병합/후처리할 때의 의존성과 구분한다. [hook](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua), [yt-dlp FFmpeg 역할](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#dependencies)
- **화질 runtime 변경:** `ytdl-format` 변경은 이미 열린 스트림에 즉시 새 rendition을 붙이는 보장이 아니다. 앱은 위치·pause·R1·R2를 보존하고 원본 URL을 다시 resolve/load하는 설계를 권한다. `ytdl_hook-all_formats=yes`로 rendition들을 track에 노출할 수 있으나 mpv 문서는 runtime 전환이 느리고 이 목적에 적합하지 않다고 설명한다. [0.41.0 all_formats](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst), [hook](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua)
- **자막:** extractor 필터는 `ytdl-raw-options`의 `sub-langs`(예: `ko,en.*`), 자동 생성 자막은 `write-auto-subs=`를 사용한다. 이는 mpv `slang=ko,en`/`sid`의 재생 트랙 선택과 다른 단계다. hook는 요청된 자막 데이터/URL을 `sub-add`로 연결하며 기본 요청은 모든 언어다. 리스트의 쉼표는 Y1 escaping 주의. [yt-dlp Subtitle Options](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#subtitle-options), [hook](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua), [mpv slang](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)
- **캐시:** v0.41.0 `cache=auto`가 기본이며 네트워크로 판단하면 cache 설정을 사용한다. 제안 시작값은 `cache=yes`, `cache-secs=20`, `demuxer-max-bytes=128MiB`; 이는 **추천 실험값**, 공식 기본값/4K 보장 수치가 아니다. packet cache와 decode/GPU frame 메모리는 다르므로 전체 탭 메모리 상한과 혼동하지 않는다. `demuxer-max-back-bytes`로 뒤쪽 보관 예산도 따로 정한다. [0.41.0 cache 문서](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)
- **buffering UI:** `paused-for-cache`, `demuxer-cache-state`, `cache-buffering-state`, `seeking`, `time-pos`, `duration` 등의 속성을 관찰한다. cache-secs를 재생 시작 전 전량 채우기 시간과 동일시하지 않는다. 라이브는 duration/seek 범위가 VOD와 다르며 실제 seekable 구간을 표시한다. [속성](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/input.rst), [cache-pause](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)
- **탐색:** VOD에서는 기존 mpv `seek absolute+exact`/keyframes 정책을 재사용한다. 실제 성공·지연은 HTTP/manifest/보관 구간에 달리고 캐시 밖은 추가 네트워크 요청이 필요할 수 있다. live/종료된 live·서명 만료 URL의 seek는 별도 수용 시험 대상이다. [seek](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/input.rst), [network/cache](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)

## Y5 R1·R2 와의 관계

- **공통 파이프라인:** resolver 이후는 libmpv가 연 미디어 stream이므로 gpui HWND/render API, Tauri native surface, egui+glow FBO 어느 UI에서도 기존 pause·volume·speed·track·filter 제어 구조를 재사용할 수 있다는 **구조적 판단**이다. UI별 출력 표면·OpenGL context 계약은 계속 지켜야 하며 yt-dlp가 UI renderer를 대체하지 않는다. [ytdl_hook](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua), [render API](https://github.com/mpv-player/mpv/blob/v0.41.0/include/mpv/render.h)
- **R1:** `hwdec=auto`(현재 tag에서 auto-safe는 동의어) ↔ `no` runtime 변경과 SW fallback은 로컬 파일과 같은 mpv 기능이다. VP9/AV1/H.264 선택은 format selector, 선택된 codec의 HW 가속은 GPU decoder capability 문제다. AV1 고정 + HW ON도 GPU가 지원하지 않으면 SW가 될 수 있다. 요청값·실제 `hwdec-current`·codec·해상도를 함께 표시한다. [0.41.0 hwdec](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst), [properties](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/input.rst)
- **출력 interop:** Windows D3D11VA는 호환 VO/D3D11 또는 ANGLE 경로가 필요하고 `d3d11va-copy`는 CPU copy-back이다. 특히 egui+glow에서 일반 WGL OpenGL을 썼다는 사실만으로 D3D11VA 무복사가 되는 것은 아니다. mpv0.41 OpenGL render API 문서는 Windows에서 직접 HW decode에 ANGLE을 요구한다. [render_gl.h](https://github.com/mpv-player/mpv/blob/v0.41.0/include/mpv/render_gl.h), [hwdec 목록](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)
- **R2:** 밝기·대비·채도 출력 속성, `vf`의 blur/sharpen/denoise/deinterlace, glsl-shaders는 기존 선택한 mpv 출력 경로에서 적용한다. codec별로 R2 UI를 따로 만들 이유는 없지만 pixelformat·bit depth·색공간·인터레이스 여부에 따라 graph 협상/효과가 달라질 수 있다. R1 toggle은 영상 필터 ON/OFF와 독립으로 저장한다. [video filters·equalizer](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)
- **성능·라이선스:** CPU lavfi 필터가 필요하면 HW frame download/upload가 개입할 수 있다. 고해상도 SW AV1 + denoise의 실시간 성능은 **미확인**이다. YouTube 재생이라고 FFmpeg GPL 필터 조건이 바뀌지 않으며 `hqdn3d`·`eq`는 GPL 의존을 확인해야 한다. [FFmpeg HW transfer](https://ffmpeg.org/doxygen/8.1/hw_decode_8c-example.html), [FFmpeg configure](https://github.com/FFmpeg/FFmpeg/blob/master/configure), [mpv vf](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)
- **재로드 상태 제안:** 탭 session에 requested_hwdec, requested_filters, quality_policy, original_url, last_position, pause를 저장한다. 화질 변경·resolver 재시도·playlist 다음 항목에도 앱 정책대로 복원하되 요청값을 실제 적용 성공 상태로 오인하지 않는다. 기본 `reset-on-next-file` 정책에 의존해 우연히 유지되는 동작을 만들지 않는다. [mpv reset 옵션](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst)

| 지역 제한 | 공식 서비스·권리자의 지역 제한이 있을 수 있고 extractor/플레이어 양쪽 HTTP가 실패할 수 있음. 제한 우회를 자동 재시도 정책으로 만들지 않는 설계 | [YouTube API 정책 III.I.13](https://developers.google.com/youtube/terms/developer-policies), [mpv ytdl proxy 주의](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst) |

| 로그인 방식 | yt-dlp YouTube 안내는 OAuth 로그인 미작동 및 cookie 사용을 설명함. 일반 username/password 지원을 YouTube 로그인 보장으로 해석하지 않음 | [Extractors OAuth](https://github.com/yt-dlp/yt-dlp/wiki/Extractors#logging-in-with-oauth) |
| cookies-from-browser | `cookies-from-browser=edge`/`chrome`/`firefox` 등의 raw 옵션 전달 가능. profile 지정 syntax가 있고 browser cookie 읽기는 자동 기본이 아님. Windows 잠금·권한·암호화 방식별 성공은 미확인 | [yt-dlp Authentication/Filesystem options](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md), [FAQ](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#how-do-i-pass-cookies-to-yt-dlp) |
| 계정·쿠키 관리 | upstream은 cookie 계정 사용 시 ban 위험과 cookie rotation을 경고. 앱은 사용자 명시 선택 시에만 사용하고 cookie 내용·signed media URL·token·profile 경로는 로그/telemetry에서 제거하는 설계 | [Extractors](https://github.com/yt-dlp/yt-dlp/wiki/Extractors#exporting-youtube-cookies) |
| URL 추출 성공 후 403/전송 실패 | 추출 URL은 같은 IP·headers/cookies 등의 조건이 필요할 수 있음. 원본 watch URL을 저장하고 실패 시 제한된 재resolve를 제안. 직접 URL 영구 저장을 기본으로 삼지 않음 | [FAQ](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#i-extracted-a-video-url-but-it-does-not-play-on-another-machine--in-my-web-browser) |

- **libmpv 이벤트:** `mpv_command_async`의 명령 접수/완료는 실제 영상 재생 성공과 구분한다. `START_FILE` → `FILE_LOADED`/buffer 속성 → 재생 상태를 관찰하고 `END_FILE`의 reason·error로 종료를 분류한다. `FILE_LOADED`는 headers 읽기 후 decoding 시작 시점이지 끝까지 재생 성공 보증이 아니다. [0.41.0 client API](https://github.com/mpv-player/mpv/blob/v0.41.0/include/mpv/client.h)
- **end-file:** `ERROR`일 때 `mpv_event_end_file.error`는 대략적인 mpv 오류 코드다. `EOF`·`STOP`·`QUIT`·`REDIRECT`는 별도이며 playlist로 바뀌는 `REDIRECT`를 실패 팝업으로 처리하지 않는다. playlist_entry_id와 insert id/count로 연관시킨다. [구조체·enum](https://github.com/mpv-player/mpv/blob/v0.41.0/include/mpv/client.h)
- **추출기 상세 오류:** `mpv_request_log_messages`와 `MPV_EVENT_LOG_MESSAGE`로 ytdl_hook/stream/ffmpeg 메시지를 받는다. hook가 subprocess stderr·JSON parse 실패·실행 파일 미발견 등을 로그로 남기지만 `end-file`이 “연령/지역/봇”을 안정된 enum으로 구분해 주지는 않는다. 로그 문자열 분류는 **추정적 진단**으로 표시하고 원문 sanitized 진단과 재시도 버튼을 제공한다. [hook stderr 처리](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua), [log API](https://github.com/mpv-player/mpv/blob/v0.41.0/include/mpv/client.h)
- **event pump:** UI 스레드에서 network load를 동기 대기하지 않는다. wakeup callback은 신호 전달만 하고 event loop에서 wait_event/poll 후 UI로 전달한다. 탭 close/open generation이 지난 로그·metadata가 새 탭에 붙지 않도록 한다. backoff·취소·재시도 횟수는 앱 정책이며 무한 reload는 금한다는 설계 제안이다. [async/event loop](https://github.com/mpv-player/mpv/blob/v0.41.0/include/mpv/client.h)
- **제목:** hook가 extractor JSON title을 file-local `force-media-title`에 넣으므로 앱은 `media-title` 변화를 관찰해 임시 URL 탭 제목을 교체한다. 실패 전에는 제목이 없을 수 있으므로 URL/video ID를 fallback으로 둔다. [hook](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua), [media-title](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/input.rst)
- **썸네일:** `ytdl_hook-thumbnails=none`이 기본, `best/all`은 이미지들을 영상 트랙으로 추가하는 기능이다. 이것을 “탭 UI용 thumbnail URL property가 자동 생김”으로 해석하면 안 된다. 탭 썸네일이 필요하면 별도 metadata resolver의 `thumbnail/thumbnails` JSON을 읽는 설계를 검토하되 중복 추출 요청을 최소화한다. 실제 이미지 다운로드·cache 보관과 권한은 별도 정책이다. [hook thumbnails](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua), [문서](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/options.rst), [yt-dlp fields](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#output-template)

## Y7 링크 → 탭 연결

아래는 **앱 라우팅 설계 제안**이며 YouTube URL의 영구 규격을 새로 정의하는 것이 아니다. yt-dlp Youtube extractor에는 watch·shorts·live·embed·짧은 링크 등을 처리하는 패턴과 시험 데이터가 있다. 실제 지원은 extractor 버전에 따라 바뀔 수 있다. [고정 extractor](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/yt_dlp/extractor/youtube/_video.py)

| 입력 | 앱 권장 라우팅 | 보존/검증 |
|---|---|---|
| `youtube.com/watch?v=ID` | 새 VideoTab + `Source::YouTube` session | original URL·video ID·start·quality·R1·R2 저장 |
| `youtu.be/ID` | 같은 경로로 정규화 | query의 t/list 등을 버리기 전에 해석 |
| `youtube.com/shorts/ID` | 같은 플레이어 탭 | 세로 aspect는 decoder 메타데이터로 표시, 별도 short 앱 불필요 |
| `watch?v=ID&list=LIST` | 기본은 클릭한 영상 1개 | playlist 재생은 사용자 선택으로 분리 |
| `youtube.com/playlist?list=LIST` | playlist용 한 탭/queue 또는 목록 UI | 수백 항목을 곧바로 수백 재생 session으로 만들지 않음 |

- **URL 검증:** Rust URL parser로 scheme·host·path·query를 분리하고 HTTPS·정확한 `youtube.com`/허용 subdomain·`youtu.be`를 검사한다. 문자열 `contains("youtube.com")`는 `youtube.com.attacker.example`을 오인한다. 앱의 지원 URL만 ytdl에 보내고 unknown scheme·임의 extractor 옵션으로 해석하지 않는다. URL parser 사용 이유는 **구현 설계**, extractor가 모든 입력을 안전한 YouTube 링크로 제한해 준다는 보장은 아니다. [URL parser API](https://docs.rs/url/latest/url/struct.Url.html), [extractor 허용 범위](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/yt_dlp/extractor/youtube/_video.py)
- **동일 플레이어 탭:** 기존 Text/Video pane 모델에 네트워크 Source 변형만 추가하고 같은 transport·필터·HW controls를 사용한다. tab_id/session_id/generation을 분리하고, 제목이 나중에 도착해도 처음 연 탭에 연결한다. 동일 영상 클릭 때 새 탭을 항상 열지 재활성화할지는 앱 정책이며 R3 문구대로 기본은 새 탭을 제안한다. [재사용 근거: loadfile/속성](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/input.rst)
- **playlist 기본:** hook는 `--flat-playlist`를 넣고 기본으로 `--no-playlist`를 전달한다. 다만 이는 “video+playlist URL에서 영상만”의 의미이므로 순수 playlist URL까지 단일 영상으로 축소한다고 가정하면 안 된다. `ytdl-raw-options=yes-playlist=`는 playlist 선택을 명시할 때 사용한다. hook의 playlist 결과는 mpv 내부 playlist로 전환되므로 앱의 여러 탭 목록과 동일 구조가 아니다. [hook](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua), [yt-dlp Video Selection](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md#video-selection)
- **playlist 확장 정책 제안:** 한 탭 안 queue가 첫 선택이다. 여러 탭 열기를 제공하더라도 목록만 먼저 표시하고 제한된 수만 지연 open한다. `playlist-items`/최대 항목 수·취소·private/deleted 항목 처리·현재 index를 설계한다. 목록 재생 상태와 새 탭 생성 이벤트를 혼동하지 않는다. [yt-dlp playlist 옵션](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/README.md), [mpv playlist properties](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/input.rst)
- **시작 시각:** yt-dlp JSON의 start_time/section_start를 hook가 file-local start에 반영하되 명시적인 mpv start가 있으면 덮어쓰지 않는다. 원본 `t=`를 유지해 hook 처리에 맡기거나 앱에서 `t=90`, `t=1m30s`, 지원 `start=`/fragment를 초로 정규화해 **per-load start**로 넘기는 한 가지 경로를 정한다. 둘 다 실행해 추가로 90초 이동하는 이중 적용은 피한다. start 우선순위·형식 파싱은 **앱 설계/시험 대상**이다. [hook start 처리](https://github.com/mpv-player/mpv/blob/v0.41.0/player/lua/ytdl_hook.lua), [YouTube extractor](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/yt_dlp/extractor/youtube/_video.py), [mpv loadfile/start](https://github.com/mpv-player/mpv/blob/v0.41.0/DOCS/man/input.rst)
- **저장 값:** 최근 목록에는 원본/정규 watch URL·ID·시작 위치를 저장하고 signed media URL/쿠키를 기본 저장하지 않는다. 재개는 원본 URL 재추출 후 저장 PTS로 탐색하는 방식을 제안한다. 추출 URL은 IP·headers·cookie 조건이 있을 수 있어 원본 링크와 영구 식별자로 구분한다. [FAQ](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#i-extracted-a-video-url-but-it-does-not-play-on-another-machine--in-my-web-browser)

## Y8 대안: Tauri 웹뷰의 YouTube IFrame Player API

- **기능·장점:** 공식 `YT.Player`는 play/pause/seek/volume·지원 playback rate·playlist·state/error 이벤트를 제공한다. Tauri 탭 DOM 안에 넣기 쉬우며 extractor/yt-dlp/외부 JS runtime을 앱이 관리하는 부담을 줄인다는 **평가**다. [공식 API](https://developers.google.com/youtube/iframe_api_reference)
- **R1·R2 판정:** IFrame API에는 libmpv `hwdec`·`vf`·glsl-shaders와 같은 제어가 없다. cross-origin iframe의 decoder/raw frame을 앱이 직접 다루는 통합도 아니다. 따라서 같은 플레이어의 R1·전체 R2를 유지하는 R3 대체안으로는 **부적합하다는 기술적 평가**다. iframe 전체에 CSS blur/color를 거는 것은 native video filter와 같지 않고 denoise/deinterlace도 해결하지 못한다. [API 기능 범위](https://developers.google.com/youtube/iframe_api_reference), [same-origin](https://html.spec.whatwg.org/multipage/browsers.html#cross-origin-objects), [CSS filter](https://www.w3.org/TR/filter-effects-1/)
- **품질·제약:** API의 setPlaybackQuality/getAvailableQualityLevels 등은 더 이상 지원되지 않으며 품질 강제 수단으로 삼으면 안 된다. 소유자의 embed 금지, 비공개/삭제, autoplay 정책으로 재생이 막힐 수 있다. [API revision/오류](https://developers.google.com/youtube/iframe_api_reference)
- **WebView 식별:** 공식 최소 기능 문서는 embedded player의 HTTP Referer 또는 동등한 client 식별을 요구한다. desktop WebView에서 Referer 처리가 필요하며 origin 파라미터만 무조건 넣으면 해결된다고 가정하지 않는다. IFrame 오류 153은 식별 누락, 101/150은 embedding 불허다. Tauri의 dev/prod origin·CSP·Referer 조건을 실제 배포에서 검증해야 한다. [공식 client identity](https://developers.google.com/youtube/terms/required-minimum-functionality#api-client-identity-and-credentials), [IFrame errors](https://developers.google.com/youtube/iframe_api_reference#onError)
- **제품 선택:** 필요하면 “공식 YouTube 플레이어로 열기/브라우저에서 열기”를 별도 모드로 제공할 수 있다. libmpv 화면과 같은 외형이어도 재생 엔진·설정 가능 범위는 다르다고 보여준다. 공식 player의 광고·branding·controls를 가리거나 수정하는 방식은 API 정책도 함께 확인해야 한다. [YouTube Developer Policies III.I](https://developers.google.com/youtube/terms/developer-policies)
