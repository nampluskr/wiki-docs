# TEMPLATE-DECISIONS — HERDR-DECISIONS.md 대리 응답 기록 템플릿

> 이 파일을 읽는 때: leader가 대리 응답·사람에게 올린 건·구성 안 조치를 기록할 때(`docs/HERDR-DECISIONS.md`). 작성 예시(3절)는 처음 한 번, 또는 막힐 때만 읽는다.

입구는 [README.md](README.md)다.

leader가 하위 에이전트의 질문·승인 요청을 처리할 때마다 남기는 기록이다. 프로젝트 폴더의 `docs/HERDR-DECISIONS.md`로 저장한다. 대리 응답 기준은 [OPERATING.md](OPERATING.md) 1절에 있다.

## 1. 쓰는 규칙

| 항목 | 규칙 |
| --- | --- |
| 쓰는 사람 | leader만. 하위 에이전트는 고치지 않는다 |
| 쓰는 때 | 답하거나 조치한 **직후**. 나중에 몰아서 쓰지 않는다 |
| 번호 | `D-001`부터 차례로. 지우거나 다시 매기지 않는다 |
| 고칠 때 | 이전 기록을 고치지 않고 새 번호로 덧붙인다. 예) "D-002를 바로잡음" |
| 기록 대상 | 대리 응답, 사람에게 올린 건, 구성 안의 조치(재시작 등) |
| 근거 | 출처를 적는다: `INTENT.md`, 사용자 지시, `HERDR-SETUP.md` 몇 절, 가이드 파일·절 |
| 보고 | 사람에게 보고하면 `보고` 칸을 보고 시각으로 바꾼다. 이 칸만은 나중에 고쳐도 된다 |

**구분** 값은 셋 중 하나다.

| 구분 | 뜻 |
| --- | --- |
| 대리 응답 | leader가 근거를 대고 사람 대신 답했다 |
| 사람에게 올림 | leader가 답하지 않고 사람에게 물었다. 사람의 답을 `결과`에 적는다 |
| 구성 안 조치 | 승인된 구성 안에서 leader가 한 조치. 예) 멈춘 에이전트를 같은 설정으로 재시작 |

## 2. 빈 템플릿

````markdown
# HERDR-DECISIONS — <프로젝트> 대리 응답 기록

- 구성안: docs/HERDR-SETUP.md
- 기록자: <leader 이름>
- 가이드: D:\projects\docs\guides\herdr\README.md

## 목록

| 번호 | 시각 | 에이전트 | 요약 | 구분 | 보고 |
| --- | --- | --- | --- | --- | --- |
| D-001 | YYYY-MM-DD HH:MM | <이름> | <한 줄 요약> | 대리 응답 \| 사람에게 올림 \| 구성 안 조치 | 미보고 |

## 기록

### D-001 · YYYY-MM-DD HH:MM · <에이전트 이름>

- 상황: 질문 | blocked (승인 요청) | unknown | 오류
- 질문: <에이전트 화면에서 읽은 질문을 그대로 옮김>
- 구분: 대리 응답 | 사람에게 올림 | 구성 안 조치
- 답변: <보낸 답이나 한 조치. 보낸 키나 명령이 있으면 함께 적음>
- 근거: <출처와 인용>
- 결과: <사람에게 올린 경우 사람의 답, 그 밖에는 "없음">
- 보고: 미보고
````

## 3. 작성 예시

[TEMPLATE-SETUP.md](TEMPLATE-SETUP.md) 2절의 youtube-downloader 구성안을 따라 일한 경우다. 내용과 시각은 예시다.

````markdown
# HERDR-DECISIONS — youtube-downloader 대리 응답 기록

- 구성안: docs/HERDR-SETUP.md
- 기록자: ytdl-leader
- 가이드: D:\projects\docs\guides\herdr\README.md

## 목록

| 번호 | 시각 | 에이전트 | 요약 | 구분 | 보고 |
| --- | --- | --- | --- | --- | --- |
| D-001 | 2026-11-02 10:12 | ytdl-coder | tests/ 에 새 테스트 파일 작성 승인 | 대리 응답 | 2026-11-02 12:30 |
| D-002 | 2026-11-02 10:40 | ytdl-coder | 일시정지 시 부분 파일 처리 방식 | 대리 응답 | 2026-11-02 12:30 |
| D-003 | 2026-11-02 11:05 | ytdl-coder | pytest-asyncio 설치 요청 | 사람에게 올림 | 2026-11-02 11:05 |
| D-004 | 2026-11-02 11:50 | ytdl-reviewer | 응답 없음 → 같은 설정으로 재시작 | 구성 안 조치 | 2026-11-02 12:30 |

## 기록

### D-001 · 2026-11-02 10:12 · ytdl-coder

- 상황: blocked (승인 요청)
- 질문: "Create file tests/test_queue_pause.py?"
- 구분: 대리 응답
- 답변: 승인 — 화면에 안내된 승인 키를 `herdr agent send-keys ytdl-coder <키>`로 보냄
- 근거: HERDR-SETUP.md 4절 — ytdl-coder 의 파일 수정 범위에 tests/ 포함. 사용자 지시 "테스트도 같이".
- 결과: 없음
- 보고: 2026-11-02 12:30

### D-002 · 2026-11-02 10:40 · ytdl-coder

- 상황: 질문
- 질문: "일시정지할 때 받던 파일을 .part 로 남길까요, 지울까요?"
- 구분: 대리 응답
- 답변: .part 로 남기고, 재개할 때 이어 받는다.
- 근거: 사용자 지시 "일시정지·재개 기능" — 재개하려면 부분 파일이 있어야 한다.
- 결과: 없음
- 보고: 2026-11-02 12:30

### D-003 · 2026-11-02 11:05 · ytdl-coder

- 상황: 질문
- 질문: "비동기 테스트를 위해 pytest-asyncio 를 설치해도 될까요?"
- 구분: 사람에게 올림
- 답변: ytdl-coder 에게 "사용자 확인 중, 대기" 전달
- 근거: HERDR-SETUP.md 7절 — 새 패키지 설치는 사용자에게 올린다.
- 결과: 사용자 답 "설치하지 마. 표준 라이브러리 unittest 의 IsolatedAsyncioTestCase 로 해." → ytdl-coder 에게 전달
- 보고: 2026-11-02 11:05

### D-004 · 2026-11-02 11:50 · ytdl-reviewer

- 상황: unknown
- 질문: 없음 — 리뷰 요청 후 20분간 화면 변화 없음, `agent read` 로 오류 화면 확인
- 구분: 구성 안 조치
- 답변: 패널을 닫지 않고 에이전트만 종료 후 같은 설정(Opus 5.5 · medium)으로 다시 띄우고, 같은 diff 로 리뷰 재요청
- 근거: 가이드 PLANNING.md 3.4 — 같은 역할을 같은 설정으로 다시 띄우는 것은 승인된 구성 안의 일.
- 결과: 없음
- 보고: 2026-11-02 12:30
````

D-001처럼 승인 화면에 키를 보낼 때는 화면에 안내된 키를 확인한 뒤 보낸다 ([OPERATING.md](OPERATING.md) 2절).
